# 스테레오 프레임 시간 정합 및 노출 동기화 구현안

2026-10-02. **설계안이며 아직 하드웨어/펌웨어 동기화를 구현한 것은 아니다.**
이번 추가 구현은 PC의 좌우 콘솔 수신 모니터뿐이다. BOOT.BIN과 SD는 변경하지 않았다.

## 1. 지금의 매칭과 한계

왼쪽 보드 CNN → UART0 좌표 패킷 → 오른쪽 보드 좌우 큐 → 삼각측량 경로는 있다.
그러나 양쪽의 실제 카메라 노출 시각이 없어 현재는 오른쪽 보드의 UART 수신 시각과
로컬 CNN 완료 시각으로 후보를 짝짓는다. 이 depth는 진단 전용이다.
`sync=0`, `control=-2`가 정상이며 이 값을 로봇의 새 목표로 보내지 않는다.

- `frame_id`는 각 보드의 추론 번호다. 같은 번호가 같은 장면 시각을 의미하지 않는다.
- CNN START/완료, PC 명령 송신, UART 도착 시간은 카메라 노출 시간이 아니다.
- UART0의 170-byte 패킷은 115200 8N1에서 약 14.76 ms가 걸린다.
  좌표 전송 지연이 있어도 **과거의 같은 촬영 시각끼리** 짝지을 수는 있다.
  다만 제어 입력의 지연은 별도로 관리해야 한다.
- 보드별 로컬 타이머의 시작점과 진행 속도는 다르다. 숫자만 비교하면 안 된다.

**권장 순서: 통신 확인 → 실제 프레임에 시간 붙이기 → 공통 시계 →
센서 노출 동기화 검증 → 움직이는 손 검증.**

## 2. 카메라에 실제 동기화 기능이 있는가?

확인한 제조사 자료에 따르면 OV5640은 **frame exposure 모드에서 내부/외부 frame
synchronization**을 지원한다. Pcam 5C 회로도에는 센서의 `CAM_FREX`가 별도 J3로
나오는 경로가 있다. 따라서 "이 카메라는 동기화가 불가능하다"고 단정할 근거는 없다.

- [OmniVision OV5640 Product Brief, p.2](https://digilent.com/reference/_media/reference/add-ons/pcam-5c/ov5640_product_brief.pdf)
- [Digilent Pcam 5C 회로도, p.1–2](https://digilent.com/reference/_media/reference/add-ons/pcam-5c/pcam_5c_sch.pdf)

하지만 이 자료만으로 **현재 720p RAW10 MIPI 연속 출력 모드에 그대로 적용 가능**하다고
보장할 수 없다. 현행 `OV5640_SetMode720p()`와 레지스터 테이블에는 FREX 제어가 없다.
세부 레지스터, 극성, 최소 펄스 폭, 노출/읽기 동작, 연속 촬영률, 스트로브 동작을
정식 센서 데이터시트/제조사 답변으로 확인해야 한다. 임의의 레지스터 값을 쓰지 않는다.

실물의 Pcam 모델/PCB 리비전, J3의 헤더 실장 또는 패드 접근성도 확인한다.
회로도상 센서 I/O에는 VCC1V8가 사용되므로 **JF의 3.3 V 신호를 FREX에 직접 넣지 않는다.**
해당 리비전의 전압 허용 범위를 확인하고 적절한 레벨 변환/버퍼를 설계한다.
UART용 JF 핀과 카메라 J3는 서로 다른 커넥터다. 아직 동기화용 보드 핀은 지정하지 않았다.

## 3. 실제 CNN 입력 프레임에 촬영 정보를 결합

Vivado에서 카메라 영상의 SOF 이벤트를 하드웨어 카운터로 기록하는 IP를 추가한다.
AXI4-Stream의 `TUSER`를 쓸 때는 `TVALID && TREADY`로 실제 수락된 SOF만 센다.
센서 프레임 시작/패킷 정보와 이 SOF의 관계도 확인한다.

각 캡처에는 아래 정보를 유지한다. 이는 개념상의 레코드이며 현재 구현된 구조체가 아니다.

```text
capture_seq          센서 영상 스트림 기준의 단조 증가 번호
buffer_slot          VDMA DDR 슬롯 0/1/2
buffer_generation    해당 슬롯이 재사용될 때마다 바뀌는 세대 번호
sof_ticks            하드웨어에서 latch한 프레임 시작 시각
complete_ticks       DDR 쓰기 완료가 확인된 시각
clock_epoch          양쪽이 공유하는 유효한 시간계 식별자
trigger_id           공통 FREX 방식이 확인된 경우 그 촬영 요청 번호
exposure_parameters  해당 영상에 실제 적용된 노출/읽기 타이밍 정보
```

- 슬롯 0/1/2를 capture ID로 쓰지 않는다. 슬롯은 계속 반복된다.
- SOF와 실제 VDMA 쓰기 슬롯/완료를 묶어야 한다. 스트림 단절, VDMA 오류/재시작 시
  대응을 폐기하고 다시 획득한다. 단순히 소프트웨어에서 SOF 번호를 슬롯에 modulo하지 않는다.
- PS IRQ 진입 시간을 촬영 시각으로 쓰지 않는다. IRQ는 이미 latch된 기록을 읽는 알림이다.
- 카운터와 AXI 접근/영상 클록 사이 CDC, 이벤트 FIFO overflow, 64-bit 원자적 읽기를 설계한다.
- CNN 시작 때 선택 슬롯의 세대와 촬영 정보를 snapshot하고, CNN 완료까지 보존한다.
  결과에는 시작 때의 snapshot을 붙인다. 완료 때 현재 슬롯의 정보를 새로 읽지 않는다.
- 현재 코드는 최근 완료 슬롯을 선택한다. CNN의 마지막 DDR 읽기 전에 VDMA가 그 슬롯을
  덮어쓸 가능성도 측정해야 한다. 전용 CNN 입력 버퍼로 복사하거나 슬롯 소유권을 관리한다.
  복사 도중에도 원본이 바뀌지 않게 보장하고, 세대 충돌/불완전 영상은 결과를 거부한다.

**SOF는 영상 읽기/전송 기준 시각이지 그 자체로 노출 시작/중앙 시각은 아니다.**
센서 모드별 지연과 노출 시간을 확인할 때까지 `exposure_time_verified=0`을 유지한다.
rolling shutter 모드는 행마다 관측 시각이 다르므로 주요 관절/손 마커 행의 시간 차이도
평가해야 한다. 프레임에 타임스탬프 하나가 있다는 이유만으로 전 관절을 검증 처리하지 않는다.

## 4. 공통 펄스로 두 보드 시계를 연결

오른쪽 보드를 시간 기준/master로 두는 설계를 권장한다.
오른쪽 PL이 주기적 sync 펄스를 만들고 양쪽 PL이 같은 물리 에지를 기록한다.
오른쪽도 실제 출력/루프백 에지와 입력 경로 지연을 평가한다.
이 펄스는 우선 **시계 정합용**이며 카메라 trigger와 구분한다.

```text
오른쪽 PL sync 출력 ─┬─ 왼쪽 PL sync 입력 → local_ticks_L(edge k)
                    └─ 오른쪽 기준 기록 → local_ticks_R(edge k)
공통 GND, 확인된 전압, 검증된 GPIO/PMOD 핀 및 XDC 필요
```

같은 에지 번호 k에 대해 최근 여러 측정으로 아래 변환을 구한다.

```text
right_time = scale * left_ticks + offset
```

- 시작점 offset뿐 아니라 독립 발진기의 속도 차이 scale도 추적한다.
- 에지 번호/epoch를 전달하는 제어 메시지와 재획득 handshake가 필요하다.
  현재 UART v1은 좌표 메시지만 지원한다. 새 메시지는 version/type/CRC를 포함해 설계한다.
  UART로 메시지가 도착한 시각이 아니라 **미리 latch한 같은 물리 에지**를 대응시킨다.
- 펄스 누락·번호 모호성·시계 변환 잔차 초과·재부팅 시 epoch를 무효화한다.
  잠금이 다시 성립하면 새 session/epoch로 큐를 비워 이전 시간계와 섞지 않는다.
- 반복 펄스 주기는 측정된 drift와 허용 오차로 결정한다. PS GPIO polling/IRQ 방식은
  초기 측정에는 쓸 수 있지만 지터 검증 없이 1 ms 노출 정합 근거로 승인하지 않는다.
- 공통 클록 케이블 없이 UART 왕복 timestamp만 이용하는 방안은 비대칭 지연 때문에
  정확도 한계가 있다. 현재 전송률에서 정밀 정합의 우선 방안으로 삼지 않는다.

## 5. 공통 시계로 매칭하되 센서 위상도 해결

검증된 촬영 시각을 `StereoFrameMetadata`로 만들어 현재
`stereo_board_on_result(result, metadata)` 경로에 공급할 수 있다.
현재 wire format에는 64-bit 시각, epoch, 검증 flags가 이미 있다.

- 같은 유효 epoch, 허용 시각 차이, 입력 유효성, 같은 사람/관절/마커 대응을 확인한다.
- 시계 변환/노출 추정의 불확도까지 포함해 허용 시간 오차를 판단한다.
- UART 도착 순서가 아니라 촬영 시각으로 정렬한다. 동일 캡처의 CNN 재추론은 중복으로 처리한다.
- 현재 큐는 도착 시점의 후보 중 최소 차이를 바로 선택한다. 추후 엄밀한 nearest 매칭에는
  짧은 대기 구간/watermark로 더 가까운 후보의 도착을 기다리는 정책이 필요하다.
- unmatched/too-old/epoch-invalid 프레임은 버린다. 양쪽 8-entry/250 ms 설정은
  실제 CNN 속도와 UART 지연을 측정한 뒤 조정한다. 각 입력은 한 쌍에만 쓴다.

현행 설정 테이블은 720p 60 fps다. 실제 주기는 SOF로 측정한다.
독립 센서가 60 fps로 일정하게 동작하더라도 주기는 약 16.67 ms이고,
서로 반 프레임 어긋나면 가장 가까운 영상도 약 8.33 ms 차이 날 수 있다.
**공통 시계는 이 차이를 측정할 뿐, 센서의 촬영 위상을 자동으로 맞추지 않는다.**
따라서 1 ms 제한을 걸면 결과가 거의 없을 수도 있으며 제한을 느슨하게 해서
그냥 `sync=1`로 만드는 것이 해결책은 아니다.

### 권장: FREX 공통 trigger를 검증한 후 사용

1. 센서 문서와 실물에서 지원 모드/전기 조건을 확정한다.
2. 한 master의 하드웨어 펄스를 레벨 변환해 양쪽 카메라에 분배한다.
3. 두 카메라의 출력 형식, 촬영률, 노출 시간과 노출 적용 시점을 맞춘다.
4. trigger와 각 실제 캡처의 대응을 검증한다. 누락 시 임의로 다음 영상 번호를 당기지 않는다.
5. 출력 안정성/밝기/프레임 누락, 공통 trigger→노출→SOF 관계를 측정한다.
6. CNN은 같은 trigger의 영상으로 각자 실행한다. CNN 완료 시각은 달라도 된다.
7. 같은 trigger ID와 실제 검증된 시각을 함께 사용해 오른쪽에서 삼각측량한다.
   trigger ID를 wire에 추가해야 한다면 새 버전을 정의하며 현재 frame_id를 슬쩍 재해석하지 않는다.

촬영이 맞아도 양쪽 CNN이 임의의 "최신 프레임"을 선택하면 서로 다른 trigger를 분석할 수 있다.
따라서 master가 **다음 분석 대상 capture/trigger ID를 지정**하는 스케줄러도 필요하다.
초기에는 `ARM(id)` → 양쪽 입력 버퍼 준비 확인 → 공통 trigger → 해당 캡처를 보호한 채
각 CNN 실행 → 좌표 송수신 → depth의 순서를 권장한다. ARM/ACK는 위의 새 제어 메시지다.
이는 촬영 속도를 느린 보드/CNN/좌표 전송 처리량에 맞추는 대신 대응을 명확하게 한다.
실제 촬영/출력 모드가 이 순서를 지원하는지 먼저 확인하며, free-running 방식이라면
같은 capture 시각의 슬롯을 양쪽이 선택하도록 별도 예약/보존 정책이 필요하다.
준비 ACK/프레임/결과가 빠지면 해당 쌍을 거부하고 새 입력 목표만 막는다.
동기화 펄스 생성과 기존 20 ms 제어 틱은 이 분석 스케줄러와 독립적으로 유지한다.

FREX가 현재 모드와 양립하지 않으면 제조사가 문서화한 다른 동기화 모드를 검토한다.
지원되지 않으면 공통 시각에서 2D 관절을 보간하는 별도 **근사 경로** 또는 동기화 가능한
카메라가 대안이다. 보간은 가속/가림/관절 오인에 취약하고 현재 제어 경로에 구현되어 있지 않다.
보간을 실제 동시 노출이라고 표시하지 않는다. 동시에 전원 켜기/CNN 시작만으로 대체하지 않는다.

## 6. 시간 차이가 깊이에 주는 영향과 합격 기준

정렬된 이상적 카메라에서, 일정 깊이의 점이 baseline 방향으로 일정 속도 v로
이동한다고 가정하면 작은 오차의 1차 근사는 아래와 같다.

```text
|깊이 오차| ≈ Z * |v| * |Δt| / B
```

보정 baseline 약 203.5 mm, 거리 1.5 m, 횡이동 속도 0.5 m/s라는 **가상 예시**에서는
1 ms → 약 3.7 mm, 5 ms → 약 18.4 mm다. 이것은 현 시스템의 실측 정확도가 아니다.
이 가정에서 시간차로 인한 깊이 오차를 5 mm 이내로 제한하려면 약 1.36 ms 이하가 필요하다.
픽셀 오차/보정 오차/노출 blur/rolling shutter/비선형 손동작이 추가되므로 전체 오차 예산은
더 엄격해질 수 있다. 현재 1000 µs 값은 임시 설정이지 손 추적 정확도 인증값이 아니다.

실험은 서보 PWM 비활성 상태에서 실시한다.

- 로직애널라이저/오실로스코프: 공통 펄스와 프레임 이벤트, 지원되는 노출 표시 신호를 측정한다.
  SOF나 sync 펄스만 같다는 이유로 노출이 같다고 판정하지 않는다.
- 영상: 시간 패턴을 가진 공통 광원/빠르게 움직이는 실측 표적을 함께 찍어 실제 관측 시각을 확인한다.
- 시간차 p50/p95/max, 공통 시계 잔차, matched/unmatched 비율, UART drop/CRC/overrun,
  실제 capture→depth 지연, CNN 버퍼 세대 충돌을 기록한다.
- 90/120/150 cm 등 실제 사용 거리에서 정지 표적 → 저속 이동 → 빠른 손동작 순서로 검증한다.
- `exposure_time_verified`, `fixed_geometry_verified`, `localization_quality_verified`는
  각각의 검증 근거가 있을 때만 승인한다. 재투영 오차만으로 동기화를 승인하지 않는다.
- 입력이 거부되면 새 목표만 막고 기존의 마지막 승인 목표까지 이동 후 유지 정책을 지킨다.
  20 ms 제어 틱을 CNN/통신/캡처 작업과 묶지 않는다.
