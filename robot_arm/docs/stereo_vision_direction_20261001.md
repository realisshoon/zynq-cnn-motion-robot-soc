# 스테레오 비전 depth 추진 배경 및 현재 상태 (팀 공유용)

이 문서를 처음 보는 사람 기준으로 씁니다. 아직 아무것도 확정되지 않았고, 지금은
**검증 단계**입니다 — 2보드 빌드 승인 이전 상태입니다.

## 1. 왜 이걸 하는가

손목 회전(wrist_roll) 각도가 부정확한 문제가 있습니다
(`docs/agent1_wrist_calibration_report.md` 참고). 사람 손목을 2.94도만 돌렸는데
로봇 목표각이 73도 차이가 나는 24.85배 노이즈 증폭이 실측으로 확인됐습니다.

원인: 지금 depth(카메라로부터의 거리)는 CNN이 못 주니까 어깨너비 기준 인체비율
가정(`PM_SHOULDER_WIDTH_UNIT`, `pose_reconstruction.c`)으로 역산한 "가상 depth"를
씁니다. 이게 손가락 마커 두 점(간격 약 5cm) 사이의 **상대** depth에는 너무
부정확해서, 작은 실제 회전이 큰 노이즈로 증폭됩니다.

## 2. 접근 방향

**Zybo Z7-20 + PCam5 두 대**로 스테레오 depth를 확보하는 방향입니다.
- 각 보드가 지금처럼 자기 풀 CNN을 돌림(새 하드웨어/RTL 캡처 로직 불필요, 같은
  카메라 재사용)
- 보드 간은 UART로 **좌표만** 교환(프레임당 30바이트대, 20ms 예산에 무시할 수준)
- 두 보드의 좌표를 삼각측량해서 마커(현재는 red/green, `cnn_types.h` 참고)의
  실측 depth를 얻음
- 관절(어깨/팔꿈치/손목)까지 스테레오로 확장할 수 있는지는 **아직 미정** — CNN팀
  답변으로는 관절 키포인트에 offset-보정 head가 있어 80px 격자보다 정밀할 가능성은
  있으나, 실측 전까지 모름

## 3. 현재 상태 (2026-10-01 기준)

- baseline 후보: **20cm** (roll 오차 20도 허용 기준으로 역산, 실측 전 잠정치)
- 카메라 pan/tilt 짐벌(`torso_tracker.c`, `camera_gimbal_pwm.c`) 추적 기능은
  **폐기 결정** — 스테레오는 두 카메라 상대위치가 고정이어야 성립하는데 짐벌이
  움직이면 깨짐. 소프트웨어 FIXED 모드(부팅 기본값, `AGENTS.md` 참고)만으론
  `u` 키로 실수 토글될 위험이 있어 **서보를 물리적으로 분리**할 계획
- PC용 분석 스크립트 5개 완성 (`robot_arm/tools/stereo_vision/`):
  `calibrate_mono.py`, `calibrate_stereo.py`, `triangulate_rail_test.py`,
  `joint_jitter.py`, `focus_sharpness.py`
- 보드 1대로 하는 **go/no-go 실험**(레일 위에서 카메라 이동 + 지그 촬영 +
  오프라인 삼각측량) 진행 중 — 이게 통과해야 2보드 빌드 착수
- CNN팀(pack77 RTL) 확인 완료: 관절은 80px 격자 + offset head 보정, 마커는
  별도 색검출 경로(argmax 안 탐) — 마커 centroid가 가중평균인지 셀 중심인지는
  후속 확인 필요
- 보드 쪽 SD 프레임 캡처 구현: UART `1`은 `CALIB/`(체커보드, 기본값),
  `2`는 `JIG/`(마커 검증)를 선택하고 `C`로 PPM 1장을 저장한다.
  폴더 자동 생성·폴더별 중복 없는 번호를 지원한다. 보드 실물 검증은 아직 남아 있다.
  촬영 절차는 `robot_arm/tools/stereo_vision/README.md` 참고.

## 4. 에이전트별 유의사항

**Agent1(포즈 인식) 관련 작업 중이시면**: `pose_reconstruction.c`는 go/no-go
결과 나오기 전까지 변경 계획 없습니다. 통과하면 "스테레오 성공 시 그 값 사용,
실패/가림이면 기존 가상 depth로 fallback" 구조로 확장될 예정이니, 지금 이 파일을
크게 리팩터링할 계획이 있으면 미리 조율 부탁드립니다.

**Agent3(서보/PWM) 관련 작업 중이시면**: 당장 영향 없습니다. 다만 보드 간 UART
링크가 실제로 필요해지면, 기존 UART1은 trace/콘솔로 이미 점유돼 있어서 새 포트
(EMIO 또는 Uartlite 추가)가 필요합니다 — BD/XSA 재빌드가 따라올 수 있다는 점
참고 부탁드립니다. 아직 확정 아닙니다.

**Agent4(CNN/카메라 하드웨어) 관련 작업 중이시면**: 짐벌 서보 물리 분리 작업이
생길 예정입니다. 또한 색마커(red/green) centroid 계산이 가중평균 blob
centroid인지 매칭된 셀의 기하학적 중심인지 확인 부탁드립니다 — wrist_roll
정확도에 직결되는 부분이라 중요합니다.

## 5. 아직 결정 안 된 것

- baseline 20cm 최종 확정 여부 (go/no-go 실험 결과 대기)
- 마커 vs 관절 중 어디까지 스테레오로 커버할지
- 2보드 빌드 자체의 승인 여부 (go/no-go 실패 시 IMU 등 대안으로 선회 가능)
