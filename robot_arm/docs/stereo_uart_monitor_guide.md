# 양쪽 보드 UART 디버그 스크립트 사용 설명서

## 승열3 메뉴·녹화 업데이트 (2026-10-08)

실행 명령은 그대로다. 최신 BOOT에서는 `V`의 `[REC_STATE]` 응답으로 재접속 후 이름 입력·메뉴·재생 상태를 복원한다.
`S/X`는 이름 입력을 취소하지 않는다. `ui=NAME unsaved=1`이면 녹화는 RAM에만 있으며
`l/r record name <ASCII이름>`으로 저장하거나 `l/r record cancel`로 명시적으로 취소한다.
`[REC] SAVED` 전에는 SD 저장 완료로 판단하지 않는다. 실패 시 이름/중복/용량/IO 이유를 확인한다.
`R` 요청 후 준비 상태에서 마지막 승인 목표까지 정착하고 실제 `recording started`를 기다린다.
준비 전에 ON이던 추종은 이어지며, OFF였던 추종을 자동으로 켜지 않는다. 준비 중 `R`은 취소다.
기본 용량은 자유 녹화 34.96초 + 정착 예약 6.00초, 총 40.96초다. 실제 값은 BOOT 시작 응답을 따른다.
Unity 버튼 연동·송신 바이트와 상태 조건은 [Unity UART 계약](uart_protocol_unity.md),
빌드·미검증 항목은 [승열3 릴리스](seungyeol3_release.md)를 참고한다. 아래의 과거 SD 설치 기록은 이번 BOOT 설치를 뜻하지 않는다.

로봇0·로봇1 개별/공통 명령과 시연 순서는 [명령 요약](robot0_robot1_commands.md)을 참고한다.

로봇1 집게 상한은 운영 소스에서 2300→2400µs로 조정했고 LEFT SD 설치·파일 검증을 완료했다.
기존 BOOT은 PC와 SD에 백업했다. 실제 부팅·발열은 미검증이다. 재부팅 후 `l V`의
`[GRIP_PWM] close_max_us=2400`을 확인한다.
RIGHT BOOT과 기존 레코드·가중치는 유지한다.

## 보드별 독립 로봇 제어 준비판 (2026-10-07)

새 split-board 구성의 공유 모니터 지원은 준비되었다. 새 BOOT은 **양쪽 SD 설치·파일 검증
완료 / 실물 구동 미검증** 상태다. 모니터만 바꾸어 실행해도 SD에 설치된
기존 펌웨어의 역할은 바뀌지 않는다. 운영 소스는 `captures/g_uart_tuning_20261004/G/snapshot`이다.
양쪽은 최신 공유 `final_uart0.xsa`, 고정 CNN pack `0x77D4E3BB`, 로봇 PWM OFF 부팅을 유지한다.

| USB 대상 / 보드 | 로컬 로봇 출력 | `V`의 역할 확인 | 데이터 역할 |
|---|---|---|---|
| `l` / LEFT(sub) | ROBOT1, 이 보드의 JC CH0..CH4만 출력 | `arm=ROBOT1_JC_CH0_CH4` | LEFTCNN과 UART0 좌표 송신 유지, main의 신선한 stereo A1 각도 수신 |
| `r` / RIGHT(main) | ROBOT0, 이 보드의 JB CH0..CH4만 출력 | `arm=ROBOT0_JB_CH0_CH4` | stereo A1 생성·송신, 기존 오른팔 제어 유지 |

main 보드 JC에는 ROBOT1 팔 출력을 연결하지 않는다. ROBOT1은 sub 보드 JC에서만 구동한다.
LEFT `l E/A/S/T/V/R/P`와 `l X`는 LEFT 로컬 ROBOT1을 대상으로 하고, RIGHT `r` 명령은
기존 의미를 유지한다. 소문자 CNN/카메라 명령과 LEFT 좌표 송신 역할도 유지한다.
LEFT `l S`로 로컬 추종을 끄더라도 LEFTCNN/UART 좌표 송신을 끄는 명령으로 해석하지 않는다.

새 LEFT/RIGHT BOOT을 모두 설치하고 UART0 **TX↔RX 양방향과 공통 GND**를 연결해야 한다.
LEFT 실시간 추종은 RIGHT의 신선한 A1 송신에 의존하지만 로봇0 PWM을 켤 필요는 없다.
LEFT 저장 레코드 재생은 로컬 SD로 수행한다. 촬영 동기화가 새로 구현된 것은 아니다.
배포 파일과 파일 검증 결과는 `vitis/boot/stereo_G_split_board_control_20261007/README.md`를 참고한다.

ROBOT1 LIVE는 main의 최신 stereo A1 각도를 LEFT의 로컬 A2에 넣고, LEFT 중심선 기하
**13.5/6/13 cm**로 안전검사·20 ms 궤적·PWM 적용을 수행한다. 각 보드가 성공적으로 적용한
자기 명령을 20 ms마다 녹화하고 **자기 SD**의 `0:/MOTION/`에 저장하며 자기 레코드를 반복 재생한다.
두 SD의 같은 번호·이름은 별개이며, ROBOT0 기록을 ROBOT1 기록으로 자동 복사하거나 취급하지 않는다.
이는 서보 명령 기록이며 실제 관절 위치 피드백이나 두 팔 PWM 위상 동기화의 보증이 아니다.

새 split-board에서는 수동 그리퍼 열림 때문에 `P`가 거부되어도 해당 보드의 신규 추종을 끈다.
수동 열림은 그대로 유지한다. `H`로 자동 복귀한 뒤 추종·재생을 다시 선택한다.
기존 RR 가속도 검사 때문에 이동 도중 녹화 시작은 저장 거부가 가능하므로 정지 상태에서
`R`로 녹화를 시작한 뒤 움직이는 것을 권장한다. 저장 완료 메시지 전에는 SD 저장 완료가 아니다.

기존 실행 명령과 **번호 두 번: 재생 / Backspace → Enter: 삭제** UI는 그대로다.
`l P`는 LEFT 목록, `r P`는 RIGHT 목록을 요청한다. 양쪽 목록이 함께 있으면 마지막으로 직접
요청한 쪽의 키 입력을 사용하며 `l record list` / `r record list`로 대상을 선택할 수 있다.
대상을 정하지 않은 채 양쪽 목록·이름 안내가 함께 나타나면 단독 번호·이름은 거부하고
`l/r record select <번호>` / `l/r record name <이름>`으로 명시한다. `both record ...`는 지원하지 않는다.
양쪽의 선택 번호·삭제 확인·재생 승인 대기·5초 응답 타임아웃·재부팅 초기화는 서로 독립적이다.
한쪽의 `[REC] PLAY`나 삭제 확인으로 다른 쪽 메뉴를 닫거나 명령을 보내지 않는다.

`--filter commands`에서도 늦게 도착한 LEFT/RIGHT `[REC]` 메뉴와 저장·재생·삭제 결과를
계속 표시한다. 화면의 `[L]` / `[R]`이 실제 수신 USB 포트이며, 축약 안내도 해당 `l` / `r` 명령을
사용한다. 전체 원문과 arm 역할 표시는 각 UART 로그·raw·combined 로그에 보존한다.

## 승열2 리뷰 수정판 (2026-10-07)

실행 명령과 `r R`, `r P`, `r X`, `r S` 입력은 그대로다. 실제 LEFT/RIGHT 소스는
`captures/g_uart_tuning_20261004/G/snapshot`이며 승열2 백업은 수정하지 않는다.
앞서 추가한 설정 SD 저장·이름 입력·한국어 메뉴 기능도 유지한다.

- `r R` 녹화 시작은 녹화 버퍼와 기록 시간 기준만 초기화한다. 그리퍼 닫힘 잠금,
  이동 중 그립 유지, 팔꿈치·손목 복귀 목적지와 연결 이력은 보존한다.
  녹화가 실제 손 입력을 무시하거나 물건을 반드시 잡고 있음을 보장하는 것은 아니다.
- 재생 번호를 두 번 누르면 요청 대기 상태가 된다. 보드의 `[REC] PLAY` 승인 후에만
  목록을 닫으며 거부되면 목록에서 다시 선택할 수 있다. 대기 중 중복 선택과 삭제는
  전송하지 않는다. 5초 동안 승인 응답이 없으면 목록을 유지하며 자동 재전송하지 않는다.
  응답 유실 시 보드가 이미 재생 중일 수 있으므로 `r V` 또는 `r P`로 상태를 확인한다.
- 모니터는 `X`·`S` 전송 앞에 ESC 바이트를 붙인다. 새 펌웨어는 레코드·필터·설정
  프레임과 색상/카메라 메뉴를 취소한 뒤 정지 명령을 처리한다. 취소한 메뉴의 미적용
  값은 버리고 이미 적용된 설정은 유지한다. 소문자 `x`·`s` 및 이름 안의 `X`·`S`는
  기존 의미를 유지한다. RAW 로그/audit에서 전송 길이가 2바이트인 것은 정상이다.
- 미완성 레코드·필터·설정 프레임은 RX가 비어 있고 마지막 처리 바이트 이후 250ms를
  초과하면 폐기한다. 늦게 도착한 꼬리 문자열은 CR/LF, 새 프레임 시작 또는 정지 명령까지
  버려서 `E`·`A` 등이 뜻하지 않게 실행되지 않도록 한다. 사용자가 숫자를 입력하는
  색상 메뉴에는 이 250ms 타임아웃을 적용하지 않는다.
- `l/r/both t` 또는 `r V`에서
  `[UART] stop_escape=1 protocol=ESC_X_S frame_timeout_ms=250 role=...`을 확인한다.
  기능 지원을 보지 못했으면 모니터가 경고한다. 구형 BOOT에서는 메뉴 또는 잘린 명령에서
  정지 명령으로 탈출하는 것을 보장하지 않는다. 새 모니터만 재실행해서는 펌웨어 문제가
  고쳐지지 않으며 해당 보드의 새 BOOT 설치와 재부팅이 필요하다.
- `r S`는 새 비동기 추종 목표만 차단한다. 기존 승인 목표까지의 이동을 즉시 중단하는
  비상정지 명령이 아니다. `r X`는 PWM OFF이므로 팔이 처지거나 물건이 떨어질 수 있다.
  UART는 foreground polling이며 SD I/O 중 응답이 지연될 수 있다. 하드웨어 비상정지를
  대체하거나 응답 지연 상한을 보장하는 기능이 아니다.

대상: `tools/stereo_vision/monitor_stereo_uart.py`, 2026-10-04 소스 버전.
두 보드의 USB 콘솔 로그를 한 터미널에 모으고, 필요할 때 왼쪽·오른쪽을 지정해 명령을 보낸다.
이 설명서의 명령은 `robot_arm` 폴더에서 실행한다. UART 모니터와 fake-port 테스트는
공유 소스에 포함한다. 촬영/캘리브레이션 도구와 로그/실험 산출물은 별도 로컬 자료다.

## 1. 빠른 시작

### RIGHT 그립 이동 유지 (2026-10-07 G 배포판)

- 기존 닫힘 확인·히스테리시스·1.5초 유지는 유지한다. 신선한 닫힘 확인 후 팔 출력이 움직이면 닫힘을 유지한다.
- 팔꿈치·손목 4축의 HAL 적용 성공 명령으로 최근 60~120ms 이동량을 계산한다. 최대 축 속도 8°/초 이상이면 이동, 3°/초 이하가 200ms 유지되면 저속으로 본다. 실제 위치 피드백은 아니다.
- 저속 확인 이후에도 **새로운 신선한 열림 3회**가 필요하다. 중복·누락·카메라 소스 변경·250ms 초과 입력 공백은 열림 확인을 다시 시작한다. 출력 관측이 100ms 넘게 끊기면 정지로 간주하지 않는다.
- 이동 중에는 열림이 수초 지연될 수 있다. 물건을 받쳐 둔 뒤 `r O`로 수동 열림을 유지할 수 있다. **물건이 떨어질 수 있으므로 주의한다.** `r H`로 자동 그립을 복구한다. 두 명령은 RIGHT·LIVE·PWM ON에서만 동작하고 A2 안전검사를 우회하지 않는다. `r O`는 `r A`/`r S`나 입력 세션 변경으로 자동 취소되지 않는다. 재부팅하면 취소된다. 수동 열림 중 재생은 거부한다.
- `O`, `H` 전송에는 `--interactive --allow-motion-commands`가 필요하다. 기존 실행 명령은 동일하다.
- 원본 `GR`, `GH` 형식은 유지한다. 추가 진단은 `GM,rsid,lsid,t_ms,armed,locked,moving,speed_deg_s,open_count,manual_open`이다. `--filter commands`에서는 진단이 화면에 숨겨져도 원본 로그에는 저장된다.
- 이 기능은 미끄러짐을 직접 감지하거나 그립 힘을 높이지 않는다. 실물 검증: 스펀지 잡기 → 이동 → 멈춤 → 손가락 펴기. LEFT BOOT과 SD 가중치는 변경하지 않는다.

2026-10-07 열림 보완 시험판은 위 저속 해제 조건에 **지속적인 강한 열림 해제**를 추가한다. 기존 닫힘 잠금이 끝난 뒤 새 유효 열림 값이 0.8 이상으로 800ms 확인되면, 팔이 움직여도 그 열림 목표를 허용한다. 누락 200ms 이내에는 확인 이력만 보존하며, 누락 자체나 중복 프레임으로 열지 않는다. 소스 변경·250ms 초과 신선한 관측 간격·약한 열림/닫힘 입력은 확인을 다시 시작한다. 출력 관측이 오래된 경우에도 해제하지 않는다. 기존 1.5초 닫힘 유지·A2 안전검사·`r O`/`r H`는 그대로다. 이동 중 물건을 놓을 수 있으므로 스펀지로 먼저 검증한다. 새 진단은 `GO,rsid,lsid,t_ms,pending,count,confirmation_age_ms`이고 기존 GR/GH/GM 형식은 변경하지 않는다. 시험 BOOT 설치 전까지는 SD의 기존 동작이 유지된다.

### 외부 G 칼만 시험판 (2026-10-05)

외부 G 계수 명령은 일반 모니터 대신 다음 실행기를 사용한다. 기존 `both m`/`both value`/`both enter`도 유지한다.

```powershell
python tools/stereo_vision/filter_acg/g_variant/uart_tuning/monitor_stereo_uart.py --left COM3 --right COM4 --interactive --allow-motion-commands --filter commands --format plain
```

RIGHT `stereo_G_short_gap_history_20261005` BOOT은 `r filter show`에
`time_policy=G_SHORT_GAP_HISTORY history_hold_us=500000`을 표시한다.
신선도 250 ms와 이력 보존 500 ms는 별개다. 500 ms 이하의 짧은 무효 입력에는 이력만 보존하며,
오래된 좌표를 새 유효 출력으로 보내지 않는다. 긴 공백은 필터를 초기화하되 공백만으로 추가
재획득 대기를 만들지 않고, 세션 변경/150 mm JUMP의 기존 3개 후보 검사는 유지한다.
`r filter kalman xy 8`, `r filter kalman z 70`, `r filter kalman accel 500`,
`r filter kalman velocity 500`은 기존대로 RAM 계수를 조정한다. 운영 A/LEFT에는 이 정책을 넣지 않았다.
자세한 범위·단위·검증은 `tools/stereo_vision/filter_acg/g_variant/uart_tuning/README.md`를 참고한다.

PowerShell 또는 Windows Terminal을 연다. 에디터의 읽기 전용 Output 창이 아니라 **키보드 입력이 가능한 터미널**을 사용한다.

```powershell
cd D:\Working\zynq-cnn-motion-robot-soc\robot_arm
python -m pip install pyserial
python tools/stereo_vision/monitor_stereo_uart.py --list-ports
```

프로젝트 경로와 COM 번호는 자기 PC에 맞게 바꾼다. 현재 사용 구성은 왼쪽 `COM3`, 오른쪽 `COM4`다.
보드별 USB를 하나씩 연결해 번호를 확인하면 좌우를 혼동하지 않는다.
ComPortMaster, 다른 모니터 스크립트 등에서 **두 COM 포트를 모두 닫고** 실행한다.

```powershell
python tools/stereo_vision/monitor_stereo_uart.py --left COM3 --right COM4
```

기본값은 수신 전용이다. 보드에 명령을 보내지 않으며 `Ctrl+C`로 종료한다.

### 로그 보기와 명령 입력

```powershell
python tools/stereo_vision/monitor_stereo_uart.py --left COM3 --right COM4 --interactive --filter all
```

실행 중 같은 터미널에 `l ?` 또는 `r ?`를 입력하고 Enter를 누르면 해당 보드의 도움말을 요청한다.
로그가 입력을 밀어내면 `--filter all` 대신 `--filter console`을 사용한다.
console은 TK/CN 등 빠른 TRACE만 숨기고 컬러 메뉴·적용 응답·오류·[ST]를 표시한다.
전체 수신 로그는 디스크에 계속 저장한다.
초기 문제 진단, 도움말 조회, 마진 설정에는 `--filter all`을 사용한다.

### 내가 보낸 명령의 응답 중심으로 보기 (간결한 화면)

```powershell
python tools/stereo_vision/monitor_stereo_uart.py --left COM3 --right COM4 --interactive --filter commands --format plain
```

평소에는 조용히 수신·저장하다가 `r ?`, `r T`, `r m`처럼 사용자가 보낸 명령의 대상에
응답 창을 연다. 주기적 TK/CN/CAM 및 RAW/PAIR/PIX/PG TRACE와 `[ST] tx=...` 통계는 창 안에서도 숨긴다.
`T/A/S/X`의 `async_test=... pwm=... result=...` 형식인 명시적 `[ST]` 응답은 표시한다.
RIGHT 필터 명령의 `ACK`/`FILTER` 응답도 해당 전송의 응답 창 안에서 표시하며 전체 원문은 파일에 보존한다.
허용된 명령의 UART write 직전에 창을 열며 기본 3초, `--response-window 5`로 5초를 지정할 수 있다.
여러 줄 도움말과 줄바꿈 없는 메뉴 프롬프트도 처리하고, 숫자 메뉴는 항목을 보낼 때마다 창을 다시 연다.
다음 항목을 오래 생각해도 이후 `l/r/both value` 또는 `l/r/both enter` 입력으로
각 대상의 새 창이 열리므로 자동 전송은 필요 없다.

`--format plain`은 `[L]`/`[R]`만 붙이고 화면 UTC·긴 JSON 전송 이력을 뺀다.
`[HOST] r T: sent (R 1/1 sent)`처럼 전송 결과를 간결하게 표시한다.
ComPortMaster와 **전송되는 UART 바이트는 동일**하지만 좌우 태그·호스트 결과를 추가하므로
완전히 같은 원시 터미널 화면은 아니다. 디스크에는 기존 전체 UTC 로그·JSON audit·원시 바이트를 보존한다.

**응답 분리는 휴리스틱이다.** 펌웨어에 요청 ID가 없어 창 안의 다른 일반 메시지·비동기 오류나
USB에 이미 쌓여 있던 출력을 정확히 구분할 수 없다. 창 밖의 늦은 응답은 보이지 않을 수 있다.
정확한 장애 진단에는 `--filter all` 또는 저장된 전체 로그를 확인한다.
이미 수신 중이던 미완성 줄은 새 명령 응답으로 소급 표시하지 않는다.
`r q`로 보드 UART 출력을 숨기면 **응답 없이** 조용해질 수 있다. 전송 결과와 PC 안내는 남으며,
이것은 CNN/PWM/추종 중지가 아니다. 다시 켜는 `q`도 사용자가 직접 보낸다.

### 로봇 제어 명령까지 허용

```powershell
python tools/stereo_vision/monitor_stereo_uart.py --left COM3 --right COM4 --interactive --allow-motion-commands --filter commands --format plain
```

이 옵션은 운동 관련 명령의 **PC 측 차단을 해제**할 뿐, PWM이나 추종을 자동으로 켜지 않는다.
서보 전원·팔 지지·홈/마지막 명령 자세·작업 공간을 확인한 뒤 사용한다.
현재 카메라는 물리적으로 고정한다. 새 split-board BOOT 설치 후에는 `l`이 LEFT 로컬 ROBOT1,
`r`이 RIGHT 로컬 ROBOT0을 제어한다. 설치 전에는 기존 보드 역할을 따른다.

## 2. 연결과 실행 옵션

| 옵션 | 의미 |
|---|---|
| `--left COM3` | 왼쪽 보드 USB 콘솔 포트 |
| `--right COM4` | 오른쪽 보드 USB 콘솔 포트 |
| `--baud 921600` | 두 USB 콘솔에 적용할 속도. 기본값 921600, 8N1 |
| `--filter all` | 전체 로그 표시. 기본값 |
| `--filter stereo` | 화면에는 `[ST]` 로그만 표시. 전체 수신 로그는 디스크에 저장 |
| `--filter console` | 빠른 TRACE를 숨기고 메뉴·명령 응답·CE/EV·[ST] 표시. 명령 작업 권장 |
| `--filter commands` | 사용자가 명령을 보낸 대상의 응답 창에서만 표시. 주기적 TRACE/ST 제외. `--interactive` 필수 |
| `--response-window 3` | commands 필터의 대상별 응답 창(초). 기본 3초, 양의 유한한 값 |
| `--format tagged` | 화면 UTC + L/R 태그 + 상세 호스트 JSON. 기본값 |
| `--format plain` | 화면 L/R 태그 + 간결한 호스트 전송 결과. 파일은 전체 형식 유지 |
| `--interactive` | 터미널 명령 입력 활성화 |
| `--allow-motion-commands` | E/X/A, R/P, 카메라 운동 관련 키 차단 해제. `--interactive` 필수 |
| `--output captures/debug01` | 새 로그 폴더 지정. 기존 폴더는 덮어쓰지 않음 |
| `--list-ports` | 사용 가능한 COM 포트 표시 후 종료 |
| `--help` | 스크립트 옵션 설명 표시 후 종료 |

USB 콘솔은 **UART1 / 921600**, 보드 간 좌표 통신은 **UART0 / 115200**이다.
`--baud`를 바꿔도 보드 간 통신 속도는 바뀌지 않는다.
TRACE를 끈 별도 펌웨어는 USB 콘솔도 115200일 수 있으므로 빌드 설정을 확인한다.

현재 스크립트는 서로 다른 **양쪽 포트를 모두** 요구한다. 한쪽 COM만 지정하는 모드는 없다.
프로세스 실행 중에는 모드·필터가 바뀌지 않으므로 옵션 변경 시 종료하고 다시 실행한다.

## 3. 터미널 입력 문법

대상은 소문자 `l`, `r`, `both`이고, 명령 키는 **대소문자를 구분**한다.

| 입력 | 동작 |
|---|---|
| `l ?` | 왼쪽 도움말 |
| `r ?` | 오른쪽 도움말 |
| `both ?` | 양쪽 도움말. 왼쪽 다음 오른쪽으로 순차 전송 |
| `r t` | 오른쪽 CNN 상태 |
| `r p` | 오른쪽 CNN 하드웨어 identity |
| `r r` | 오른쪽 마지막 CNN 결과 |
| `r d` | 오른쪽 CNN 진단 덤프 |
| `l q` / `r q` | 해당 보드 UART 출력 mute/resume 토글. CNN·로봇은 계속 동작 |
| `r z` | 오른쪽 로봇 TRACE만 mute/resume 토글 |
| `q` | PC 모니터 종료. 보드에는 전송하지 않음 |

일반 `r t` + Enter는 보드에 `t` **한 바이트만** 보내며 CR/LF는 덧붙이지 않는다.
Enter는 PC 입력을 확정하는 키다. ComPortMaster에서 보드에 직접 한 글자를 보내는 방식과 구분한다.

- 빈 Enter는 무시한다. 숫자 메뉴에서 값을 유지하려면 반드시 `r enter`처럼 입력한다.
- 대상 없는 `m`, `E` 등은 잘못된 입력이다. `r m`, `r E`처럼 보드를 지정한다.
- `r p`와 `r P`, `r x`와 `r X`, `r a`와 `r A`, `r t`와 `r T`는 다른 명령이다.
- `both`는 순차 전송이며 동시 전송·원자적 적용·프레임 동기화가 아니다. 로봇은 `l`/`r` 대상별 응답을 확인한다.
- `both m`은 양쪽이 모두 일반 콘솔에 있을 때, `both value`/`both enter`는 양쪽이 같은 메뉴의
  같은 항목 프롬프트에 있을 때만 사용한다. 한쪽이 다른 항목이면 `l`/`r`로 별도 진행한다.
- `[HOST] command`의 `sent`는 PC 쓰기 성공이다. **보드 명령 실행 성공은 보드 응답으로 확인**한다.
- 자동 시작 명령, 종료 명령, 재연결, 재전송은 없다.

### RIGHT 런타임 필터 설정

필터 설정은 `--interactive`에서 **`r` 대상만** 허용한다. `l filter ...`와
`both filter ...`는 PC에서 거부하여 어느 보드에도 전송하지 않는다.
기존 `both m`/`both value`/`both enter`는 그대로 사용할 수 있다.
필터 명령에는 `--allow-motion-commands`가 필요하지 않으며 PWM·비동기 추종을 켜지 않는다.

| PC 입력 예 | 실제 UART 바이트 (`\r` = CR, LF 없음) | 값 범위·최소 단위 |
|---|---|---|
| `r filter show` | `~F,SHOW\r` | 현재 설정 조회 |
| `r filter default` | `~F,DEFAULT\r` | 해당 BOOT의 기본 설정 복원 |
| `r filter 2d ema tau 0.10` | `~F,EMA,100000\r` | τ 0.001..1 s, 0.000001 s 단위; 정수 µs |
| `r filter 3d min 0.5` | `~F,MIN,500\r` | 최소 cutoff 0.01..10 Hz, 0.001 Hz 단위; 정수 milliHz |
| `r filter 3d beta 0.001` | `~F,BETA,1000\r` | β 0..0.1 /mm, 0.000001 /mm 단위; 계수 × 1,000,000 |
| `r filter 3d derivative 1` | `~F,DERIVATIVE,1000\r` | 미분 cutoff 0.01..10 Hz, 0.001 Hz 단위; 정수 milliHz |

필터 이름·설정 키는 표의 소문자 문법만 받는다. 값은 ASCII 숫자와 선택적인 소수점으로
구성하며 소수점 앞뒤에 숫자가 있어야 한다. 부호·지수·NaN/Infinity·쉼표·임의 원시
payload는 받지 않는다. `decimal.Decimal`로 원래 정밀도를 보존하고 위 정수 배율로
**정확히 표현되는 값만** 전송한다. 예를 들어 τ `0.1000001`, min `0.5001`은
반올림하지 않고 거부한다. `0.1000000`처럼 의미 없는 끝자리 0은 허용한다.

운영 및 외부 비교 BOOT의 필터 순서는 다음과 같다. C/G는 별도 빌드이며 PC의 런타임
프로필 선택 명령이 아니다. 비교 BOOT의 지원 여부·적용 결과는 `ACK`/`FILTER`로 확인한다.

| 프로필 | 삼각측량 전 2D | 삼각측량 후 3D |
|---|---|---|
| 운영 A (기본) | 시간 EMA τ=0.10 s | One Euro min=0.5 Hz, β=0.001 /mm, derivative=1 Hz |
| 외부 C | 약한 시간 EMA τ=0.03 s → 2D One Euro | 운영 A와 같은 3D One Euro |
| 외부 G | 시간 EMA τ=0.10 s | 상수 속도 Kalman3D (3D One Euro를 대체) |

이 명령과 기본값은 **런타임 필터를 구현한 새 RIGHT BOOT**이 필요하다. PC 스크립트만
바꿔도 이전 펌웨어가 명령을 지원하지는 않는다. 새 BOOT 빌드·패키징·설치는 상위 통합
담당의 작업이다. 기존 BOOT에 새 프레임을 보내 지원 여부를 시험하지 않는다.
변경은 실행 중 RAM에만 적용하고 SD에 저장하지 않으며 재부팅하면 BOOT의 기본값으로
돌아간다. `sent`는 PC 전송 성공이므로 적용 성공은 보드의 `ACK`/`FILTER`로 확인한다.
commands 화면에서 응답이 늦어 숨겨졌다면 저장된 전체 로그를 확인한다.

하드웨어 ABI `0x77D4E3BB`와 SD 가중치·SHA sidecar 계약, PWM/비동기 추종 부팅 OFF는
유지한다. 필터 설정은 프레임 matching·원시 입력 승인·JUMP/재획득 기준·A1 각도 EMA·
A2 안전검사·20 ms 궤적 정책을 변경하지 않는다.

## 4. RGBY 마진 조정

`--interactive --filter commands --format plain`, `--filter console` 또는 `--filter all`로 실행한다.
`m`은 해당 보드의 연속 CNN 추론을 중단한다.
로봇이 활성화된 상태라면 마지막 승인 목표까지 이동 후 유지할 수 있으므로 안전한 시험 상태에서 설정한다.

### 오른쪽 빨강 마진만 40으로 변경하는 순서

1. `r m`을 입력한다.
2. 첫 항목 `red margin ... Enter=keep]:` 프롬프트가 보이면 `r value 40`을 입력한다.
3. 이후 각 프롬프트마다 `r enter`를 입력해 기존 값을 유지한다. 남은 항목은 **12개**다.
4. 마지막 항목까지 완료하고 `RGBY settings applied` 응답을 확인한다.
5. 오른쪽 연속 추론이 꺼져 있는 것을 확인한 뒤 `r a`로 재개한다. `a`는 토글이므로 반복 입력하지 않는다.

아래 문법을 사용하며, 프롬프트를 확인하면서 한 항목씩 입력한다.

```text
r m
r value 40
r enter
```

위 예의 `r enter`는 다음 한 항목만 처리한다. 메뉴가 끝날 때까지 각 프롬프트에서 반복한다.
왼쪽만 설정하려면 `l m`, `l value 40`, `l enter`, `l a`를 사용한다.

| 입력 | 전송되는 내용 |
|---|---|
| `r value 40` | 숫자 `40` + CR. 현재 항목 확정 |
| `r enter` | CR 한 바이트. 현재 값 유지 후 다음 항목 |
| `both m` | 양쪽 메뉴 진입. 각 보드의 첫 프롬프트 확인 필요 |
| `both value 40` | 양쪽에 숫자 `40` + CR 순차 전송 |
| `both enter` | 양쪽에 CR 한 바이트씩 순차 전송. 각 현재 값 유지 |
| `r 1` | `1` 한 바이트만 전송. 숫자 항목을 확정하지 않음 |

`value`는 ASCII 십진 숫자 1~6자리만 허용한다. 음수·소수·임의 문자열은 지원하지 않는다.
`both value`와 `both enter`도 지원하지만 **양쪽의 같은 항목 프롬프트를 확인한 뒤에만** 사용한다.
숫자 메뉴 밖에서 보내지 않는다. 메뉴 항목별 허용 범위 검사는 펌웨어가 수행한다.
스크립트는 현재 메뉴·항목을 자동 추적하지 않으며 전체 입력, 적용, CNN 재시작도 자동 수행하지 않는다.

### 양쪽 빨강 마진 40·최소 밝기 100 설정

1. 양쪽 모두 일반 콘솔인지 확인하고 `both m`을 보낸다.
2. `[L]`과 `[R]` 모두 **red margin** 프롬프트이면 `both value 40`을 보낸다.
3. 2~5번 항목마다 양쪽 프롬프트가 같은 항목인지 확인한 뒤 `both enter`를 한 번씩 보낸다(총 4회).
4. 양쪽 모두 6번 **red minimum brightness** 프롬프트이면 `both value 100`을 보낸다.
5. 7~13번 항목마다 확인 후 `both enter`를 한 번씩 보낸다(총 7회).
6. **양쪽 모두** `RGBY settings applied`를 확인한다. 양쪽 연속 추론이 OFF인 것을 확인한 뒤에만
   `both a`로 재개한다. `a`는 토글이므로 한쪽만 OFF이면 해당 보드에만 `l a` 또는 `r a`를 보낸다.

여러 줄을 한꺼번에 붙여넣지 않는다. 매 입력 후 양쪽 프롬프트를 보고 진행한다.
`both enter`는 양쪽의 현재 값을 각각 유지하므로, 기존 값이 다르면 같게 만들어 주지 않는다.
예를 들어 초록 마진도 양쪽 30으로 맞추려면 2번 항목에서 `both value 30`을 사용한다.

`[HOST] both value 40: sent (L 3/3 sent, R 3/3 sent)`는 두 PC write 성공을 뜻할 뿐
동시 적용·보드 실행 성공을 보장하지 않는다. 왼쪽 성공 뒤 오른쪽 실패가 가능하며,
각 보드의 요청/전송 바이트 수와 `sent`/`failed`/`not_attempted`를 audit에 남기고 수신기를 종료한다.
짧은 쓰기·예외의 나머지 바이트를 자동 재전송하거나 앞서 성공한 보드의 설정을 되돌리지 않는다.
재실행은 보드 메뉴를 초기화하지 않는다. 실제 양쪽 프롬프트/전체 로그를 확인하고
`l value`/`l enter`, `r value`/`r enter`로 엇갈린 항목을 별도 처리한다.

### 실제 메뉴 13개

| 순서 | 항목 | 허용 범위 |
|---|---|---|
| 1 | 빨강 margin | 0..255 |
| 2 | 초록 margin | 0..255 |
| 3 | 파랑 margin | 0..255 |
| 4 | 노랑 R-G 최대 차이 | 0..255 |
| 5 | 노랑 R/G와 B의 최소 차이 | 0..255 |
| 6 | 빨강 최소 밝기 | 0..255 |
| 7 | 초록 최소 밝기 | 0..255 |
| 8 | 파랑 최소 밝기 | 0..255 |
| 9 | 노랑 최소 R | 0..255 |
| 10 | 노랑 최소 G | 0..255 |
| 11 | 노랑 최대 B | 0..255 |
| 12 | 최소 검출 taps | 1..262143 |
| 13 | 색 활성화 mask | 0..15: R=1, B=2, G=4, Y=8 |

설정은 마지막 항목까지 입력해야 한꺼번에 적용된다. 범위를 벗어나면 펌웨어가 변경 없이 메뉴를 종료한다.
mask 15는 네 색 전부 활성화라는 뜻이다. `m` 설정을 PC 로그에 저장하는 것과 보드 설정의 영구 저장은 별개이며,
이 모니터는 재부팅 후 설정을 자동으로 복원하지 않는다.

2026-10-04 수정 소스의 부팅 margin 기본값은 R/G/B = **40/30/50**, 빨강 최소 밝기는 **100**이다.
최소 밝기는 빨간 마커 검출 임계값이지 카메라 노출·센서 밝기 설정이 아니다.
`m`으로 수동 변경할 수 있지만 영구 저장하지 않으므로 재부팅하면 소스 기본값으로 돌아간다.
이 기본값은 새 BOOT으로 교체해야 반영된다. PC 모니터만 업데이트해도 펌웨어 기본값이 바뀌지는 않는다.

줄바꿈 없는 `Enter=keep]:` 프롬프트도 표시된다. `--filter stereo`에서도 이 프롬프트는 예외로 보이지만,
나머지 메뉴 안내와 적용 응답이 숨겨질 수 있으므로 설정에는 `--filter console`을 권장한다.
`--filter commands`에서는 각 전송의 대상 응답 창 안에서 프롬프트와 적용 응답을 표시한다.

## 5. 보드별 로봇 PWM과 양안 시험

`r X`는 녹화·재생을 LIVE로 종료하고 완료된 녹화 구간은 보존한다. 수동 OFF 동안에는
궤적·재생·속도 이력을 진행하지 않는다. `r E` 성공 직후 LIVE 틱 없이 `r P`를 보내더라도
정지 전 속도를 복원하지 않는다. 이미 ON인 상태의 `r E`는 현재 궤적을 초기화하지 않는다.
수동 `X` 후 OFF 상태의 `R`/`P`는 `BUSY`로 거부한다. `E` 성공 이후 녹화·재생을 시작한다.

기존 RIGHT 명령과 조건을 유지하며 새 split-board BOOT에서 LEFT 로컬 제어를 추가한다.
양쪽 모두 부팅 시 로봇 PWM OFF, 로컬 추종 OFF다. LEFT는 좌표 송신도 계속 담당한다.
`--interactive --allow-motion-commands --filter all`로 실행하고 아래 순서를 **수동으로** 진행한다.

| 입력 | 의미 |
|---|---|
| `l V` / `r V` | 해당 로봇 PWM·모드·arm 역할 조회. 실측 관절 위치는 아님 |
| `l E` / `r E` | 해당 보드 LIVE에서 마지막 성공한 HAL 명령으로 내부 궤적을 정합하고 기존 안전검사 후 로컬 PWM ON. 팔이 움직일 수 있음 |
| `l T` / `r T` | LEFT는 main 각도 수신·로컬 추종, RIGHT는 기존 비동기 양안 시험 상태 조회 |
| `l A` | LEFT E 성공 후 PWM ON·LIVE에서 main의 신선한 stereo A1 각도를 로컬 A2로 추종 |
| `r A` | 기존 E 성공 후 RIGHT PWM ON·LIVE에서 실험적 비동기 양안 입력 ON |
| `l S` / `r S` | 해당 보드의 새 로컬 목표 차단. 마지막 승인 목표까지 이동 후 유지. 토크 유지 |
| `l X` / `r X` | 해당 로봇 PWM OFF와 로컬 추종 OFF. 내부 궤적을 마지막 성공한 HAL 명령에서 정지. 토크 해제, 팔이 처질 수 있음 |

### SD 로그 동작 재생 — 2026-10-07 RIGHT 시험판

아래는 이전 `sd_replay_test_goal1` 시험판 설명이다. 현행 이름 저장/선택/삭제는 다음 절을 따른다.

`stereo_G_sd_replay_test_goal1_20261007_v2`는 SD 루트의 `MOTION.BIN`을 부팅 때만 읽는다.
크기·버전·20 ms 주기·고정 ABI `0x77D4E3BB`·CRC32와 기존 관절 범위/FK/변화량/가속도 검사를
통과하면 `[REPLAY_SD] READY ... samples=1331`이 출력된다. 파일 오류 시 재생 데이터는 비워지며
자동으로 움직이지 않는다. 재생 중 SD 접근은 없고, SD 파일 변경 후에는 재부팅해야 한다.

기존 PowerShell 모니터 명령은 그대로 사용한다. 같은 입력창에서:

| 입력 | SD 재생 시험판 동작 |
|---|---|
| `r V` | PWM/모드와 메모리에 준비된 `replay_samples`, `repeat` 조회 |
| `r E` | 기존 안전검사 후 PWM 활성화. 이 단계부터 움직일 수 있음 |
| `r P` | 시작 자세로 제한된 속도로 이동 → 재생 → 시작 자세로 복귀 → 무한 반복 |
| 재생 중 `r P` | 반복 중지, LIVE 복귀. 비동기 추종은 OFF로 남고 자동 재개하지 않음 |
| `r R` | 기존 메모리 기록 시작/종료. 종료 시 SD에서 준비한 재생 데이터를 새 기록으로 덮어씀 |

`r A`는 재생에 필요하지 않다. `r S`는 비동기 입력 차단이지 Playback 중지 명령이 아니므로
반복 중지는 `r P`를 사용한다. `r X`는 토크를 해제하므로 팔을 지지한 상태에서만 사용한다.
수동 그리퍼 열림 `r O` 상태에서는 `r H`로 자동 모드를 복구해야 재생할 수 있다.
재생 중 안전검사·HAL 실패·제어 틱 누락은 HOLD로 전환하며 자동 반복하지 않는다.

파일에는 영상이 아니라 `test_goal1`의 성공한 HAL 명령 1,230개를 재구성한 1,331개 샘플이 들어간다.
로그 각도 반올림을 완화하고 기존 속도·가속도·그리퍼 변화량 제한을 유지했다.
동작 부분은 약 26.62초이며 매회 시작 자세 복귀 시간은 별도다. 원본 구간은 약 24.57초였다.
회전축 보정과 그리퍼 속도 제한 때문에 원본 영상과 동일한 집기 타이밍/성공을 보장하지 않는다.
첫 실물 검증은 물건 없이 진행하고, 물건·팔·케이블과 복귀 경로의 간섭을 확인한다.
기록/재생 용량은 2,048개(약 40.96초)이고, 메모리 기록 자체는 SD에 자동 저장하지 않는다.
파일 형식은 little-endian `MRP1`, uint32 버전/주기µs/개수/ABI/페이로드 CRC32의 24 byte 헤더와
각 샘플의 float32 다섯 개(elbow roll, elbow pitch, wrist pitch, wrist roll, gripper norm)다.

### SD 기록 라이브러리 — 기존 RIGHT UI와 새 LEFT 지원

PowerShell 모니터 실행 명령은 그대로다:

```powershell
python tools/stereo_vision/monitor_stereo_uart.py --left COM3 --right COM4 --interactive --allow-motion-commands --filter commands --format plain
```

기존 RIGHT SD 동작은 목록의 `1 basic_1`로 등록한다. 현재는 `test_goal1` 초반 약 7.8초를
제거한 935개 샘플/18.7초 버전이다. 시작 자세 이동과 반복 복귀 시간은 별도다.
이전 루트 `MOTION.BIN`은 설치 백업으로 보존하고, 현행 저장 위치는 `0:/MOTION/`이다.
최대 32개 기록, 이름은 영문·숫자·`_`·`-` 1~24자다. 이름 중복은 덮어쓰지 않고 거부한다.

아래 RIGHT 절차는 새 split-board BOOT에서 `r`을 `l`로 바꾸면 LEFT 로컬 기록에도 적용한다.
LEFT에는 자기 SD의 목록을 사용하며 RIGHT의 `basic_1`이 자동으로 설치되지는 않는다.
LEFT 녹화 예는 `l E` → `l A` → `l R` → 동작 → `l R` → LEFT 이름 안내 대기 →
`l record name left_grab_1` → `[L] SD 저장 완료`다. main의 신선한 stereo A1 송신이 필요하다.
LEFT 재생은 `l E` → `l P` → 번호 두 번이며 `l P`로 중지한다.

| 입력 | 동작 |
|---|---|
| `r R` | PWM ON·LIVE에서 녹화 시작 |
| 녹화 중 `r R` | 새 팔/그리퍼 입력 차단, 마지막 승인 목표의 안전한 정착 꼬리까지 기록 후 이름 입력 안내 |
| 이름 안내 후 `grab_1` + Enter | 이름 지정, SD 영구 저장. 화면의 `SD 저장 완료` 확인 전에는 저장 완료가 아님. 기존 `r record name grab_1`도 지원 |
| `r P` | PWM ON·LIVE에서는 마지막 목표를 안정시켜 위치 유지 후 이름 목록 표시. 저장 직후에도 목록 표시 |
| `1` → `1` (Enter 불필요) | Windows 콘솔의 목록에서 1번 선택 후 같은 번호를 다시 눌러 안전검사·시작 자세 이동 후 무한 반복 |
| `1` → Backspace → Enter | 1번 선택 후 삭제 요청. 보드의 삭제 확인 응답을 받은 뒤 Enter로 실제 삭제 |
| Esc | 선택·삭제 확인 취소 |
| 재생 중 `r P` | 반복 중지, LIVE 복귀. 비동기 추종은 자동 재개하지 않음 |
| `r record list` | 메모리에 캐시한 SD 목록 조회. 조회 자체는 움직임/SD IO 없음 |
| `r record delete 2` | 2번 이름을 보여주고 삭제 확인 요청. 이때는 아직 삭제하지 않음 |
| `r record confirm 2` | 대기 중인 동일 번호만 삭제. 재생/녹화/움직임 중에는 거부 |
| `r record cancel` | 이름/선택/삭제 확인 취소. 재생 중지 대신 사용하지 않음 |

녹화 예: `r E` 성공 → `r A` → `r R` → 동작 → `r R` → 이름 안내 대기 →
`grab_1` + Enter → `SD 저장 완료`. 재생 예: `r E` 성공 → `r P` →
목록 확인 → 번호 선택 → 같은 번호를 다시 누르면 반복 → `r P`로 중지.
번호는 실제 목록의 ID를 사용한다. 삭제 확인 중이 아니라면 Enter만 눌러도 재생하지 않는다.
화면에는 `1. basic_1`, `2. grab_2`처럼 번호·이름만 표시하며, 원본 샘플 수·시간은 로그 파일에 보존한다.
즉시 키 입력은 Windows의 실제 콘솔에서 1~9번에 지원한다. 10~32번은
`l/r record select 10`처럼 보드를 지정한다. 파이프·파일 입력은 기존 줄 단위 입력을 유지한다.
`r record select 1`도 호환 유지한다. 키 입력은 선택한 보드의 레코드 명령으로 변환되며,
선택 메뉴 밖에서는 보드가 거부하고 `--allow-motion-commands`가 없으면 호스트가 차단한다.
이름 안내·저장·선택 중에는 팔 위치를 유지한다.
녹화 시작 전 잠시 정지한 상태를 유지한다. 이미 빠르게 움직이는 도중 시작한 기록은
첫 샘플을 정지 상태에서 재생할 수 없어 시작 가속도 검사에서 저장이 거부될 수 있다.
다시 추종하려면 선택 화면에서 `r record cancel` 후 `r A`를 보내고, 새 녹화는 `r R`로 시작한다.
`r S`는 Playback 종료 명령이 아니며 `r X`는 토크를 해제하므로 팔을 지지해야 한다.
수동 그리퍼 열림 상태는 선택도 거부한다. 선택 화면 취소 → `r H` → `r P`로 진행한다.

### 현재 설정 조회·SD 저장·복원 (승열2 이후 개선판)

이 기능은 `stereo_G_settings_menu_20261007_v3`의 새 LEFT/RIGHT BOOT을 설치해야 사용할 수 있다.
승열2 백업은 변경하지 않았다. 설정 파일은 각 보드 SD 루트의 `UARTCFG.BIN`(96바이트)이며,
직전 정상본은 `UARTCFG.BAK`으로 보존한다. 보드 역할·고정 ABI·형식·값 범위·CRC를 검사한다.
모니터를 다시 실행해서 부팅 로그를 놓쳤다면 먼저 `r t` / `l t` / `both t`로
`[CFG] supported=1`을 확인한다. 이 확인 없이는 새 설정 명령을 전송하지 않아 구형 BOOT에서의 오작동을 막는다.

| 입력 | 동작 |
|---|---|
| `r settings show` / `l settings show` | 현재 적용 중인 RGBY 설정 조회. RIGHT는 2D EMA 및 G 칼만 계수도 표시 |
| `r settings save` / `l settings save` | 현재 설정을 해당 보드 SD에 저장. `[CFG] SAVED`로 완료 확인 |
| `r settings load` / `l settings load` | SD 설정을 검사·복원. `[CFG] LOADED` 및 실제 값 확인 |
| `both settings show/save/load` | 양쪽에 순차 요청. 각 보드 응답을 따로 확인하며 원자적 일괄 적용은 아님 |

저장 범위: `m` 메뉴의 13개 RGBY 값(마진·최소 밝기·최소 검출수·enable mask),
RIGHT의 2D EMA tau 및 칼만 XY/Z 측정 표준편차·가속도·초기 속도 표준편차.
카메라 노출·AE·짐벌, 로봇 각도·속도·안전검사·필터 내부 이력, PWM/추종 활성 상태는 저장하지 않는다.

조회는 언제든 가능하지만 저장·복원은 PWM OFF, CNN 추론 OFF, LIVE이며 녹화/재생/메뉴가 없는 때만 허용한다.
RIGHT에서 목록·이름 입력 중이면 먼저 `r record cancel`, 재생 중이면 `r P`로 중지한다.
팔을 지지하고 `r S` → `r X`로 추종·토크를 끈다. `r t`로 CNN 상태를 보고 ON이면
`r a`로 끈 다음 진행 중인 프레임이 끝난 후 저장한다. `a`는 토글이므로 OFF일 때 다시 보내지 않는다.
`m` 메뉴를 끝낸 직후에는 CNN이 이미 OFF이므로 PWM도 OFF이면 바로 저장할 수 있다.
새 split-board LEFT도 목록·이름 입력은 `l record cancel`, 재생은 `l P`로 중지한다.
팔을 지지하고 `l S` → `l X` 후 `l t` 확인, 필요한 경우 `l a`로 CNN을 끄고 저장한다.

SD IO는 이 정지 상태에서만 수행한다. 반응에 시간이 걸려도 중복 전송하지 말고 `[CFG]` 완료 응답을 기다린다.
부팅 때 자동 복원하지만 CNN 가중치 SHA 검증과 PWM OFF 기본값은 그대로 유지한다.
파일이 없거나 유효한 설정이 없으면 소스 기본값으로 부팅한다. BIN이 손상되거나 없으면 유효한 BAK를 시도한다.
정상 운전 재개는 필요에 따라 `r a`(CNN OFF일 때) → `r E` → `r A`로 명시적으로 실행한다.

레코드 화면은 저장 완료 이름, 재생 시작 이름·무한 반복 안내, 재생 중지, 삭제 확인 대상 및 삭제 완료 번호를 표시한다.
원본 UART 로그는 번역·축약하지 않고 파일에 유지한다. 이름 입력은 영문·숫자·`_`·`-` 1~24자이며
예약된 단독 입력 `r`, `l`, `both`, `q`를 이름으로 쓰려면 `l/r record name <name>` 명령을 사용한다.

정착 판정은 실제 위치 피드백이 아닌 명령 속도 4축 ≤0.05°/s와 그리퍼 명령 일치를
실제 HAL 전송이 성공한 3개 제어 틱에서 확인한다. 정착 꼬리를 포함해 기록 최대 길이는 40.96초다.
기록 틱 누락·HAL 오류·안전검사 실패·끝 가속도 오류는 이름 저장을 거부한다.
녹화 종료가 곧바로 정지/파일 저장 완료를 의미하지 않으며 움직임이 남으면 정착을 기다린다.

저장은 고정 자세 HOLD 또는 PWM OFF에서만 허용한다. 16개 샘플 단위로 쓰고 sync/close 후
SD를 다시 읽어 크기·헤더·CRC를 확인한 다음 이름과 데이터를 게시한다. SD 지연 중에도
FPGA PWM은 마지막 펄스를 유지하지만 UART/foreground 제어는 지연될 수 있다.
재생 파일 로딩/선검사는 HOLD에서 하고, 실제 재생 시작 전에만 틱 기준을 새로 잡는다.
움직임이 시작된 후의 틱 누락은 기존처럼 HOLD로 처리하며 자동 재시작하지 않는다.

디스크에서는 `R0001.BIN`(동작)+`R0001.TXT`(이름) 한 쌍을 쓴다. 완성되지 않은
`.NEW`/`.NTX`나 삭제 복구용 `.DEL` 파일은 목록에 올리지 않고 덮어쓰지 않는다.
이름과 BIN이 있어도 선택할 때 전체 CRC/안전검사를 다시 통과해야 한다.
저장 실패 시 기존 기록은 유지하고 메모리 기록으로 이름 저장을 재시도할 수 있다.
삭제 부분 실패는 `DELETE_PARTIAL_REQUIRES_SD_REVIEW`로 표시하고 SD를 점검해야 한다.
외부 PC에서 파일을 바꿨다면 보드를 재부팅해 목록 캐시를 갱신한다.
`--filter commands`에서도 지연된 `[REC]` 안내/저장 결과는 표시되며 주기 좌표 로그는 계속 숨긴다.

`E` 응답이 성공인지 먼저 확인한다. 거부 시 상태를 확인하고 조건을 해결하며 강제 활성화로 우회하지 않는다.
실험적 추종은 `r E` 성공 → `r T` 조회 → `r A` 성공 확인 순서다. `r E`만으로 비동기 추종은 켜지지 않는다.
새 split-board에서는 `l E` 성공 → `l T` 조회 → `l A`로 LEFT 로컬 추종을 켠다.
기존 좌표 송신 전용 LEFT BOOT은 `l E`/`l A`를 거부하므로 새 BOOT SD 설치 여부와 arm 역할을 확인한다.

이전 BOOT에서 `X` 후 내부 궤적만 계속 진행해 `E`가 `rejected_motion_command_drift_or_HAL_failure`로
거부되던 상태는 새 소스에서 수동 OFF 시 정지·ON 전 재정합으로 처리한다. 이 소프트웨어 상태 차이만으로
재부팅할 필요는 없지만, `E`는 무조건 강제 활성화하는 명령이 아니다. 역할·LIVE 모드·명령 범위·FK 안전검사와
HAL 실패 검사는 유지한다. 이미 ON이면 새 목표를 승인하거나 거부를 해제하는 명령도 아니다.
마지막 HAL 명령은 **전송한 명령값일 뿐 실측 위치가 아니다.** OFF 중 처짐/수동 이동은 알 수 없으므로
팔을 지지하고 실제 자세를 확인한다. ON 시 홈/마지막 명령 펄스로 움직일 수 있고 `A`는 별도로 켠다.

PWM ON 상태에서 새 입력이 기하/150mm/A2 안전검사에 탈락하면 새 목표만 거부한다.
이미 승인한 목표까지 이동한 뒤 유지하며, 이후 유효한 입력이 승인되면 다시 진행한다.
직전 승인 좌표와 150mm를 비교하는 기준은 500 ms 이하까지 보존한다. 그보다 오래되거나
150mm를 넘으면 최근 유효 쌍 3개의 정지 군집 또는 일관된 이동으로 재획득한다.
이동 후보는 각 샘플 간 ≤150mm·수신 기반 속도 ≤1500mm/s·선형 예측 오차 ≤50mm를 요구한다.
시간이 지났다고 단일 도약을 자동 승인하거나 A2 안전검사를 완화하지 않는다.
신선도 250 ms는 그대로다. 같은 세션의 300 ms 공백 뒤 신선한 150mm 이내 좌표는 즉시
승인하며, 정확히 500,000 µs는 이력 유지·500,001 µs부터는 장기 공백 재획득이다.
필터는 실제 마지막 갱신 시각을 사용하고 무효점은 출력하지 않는다. 손가락 누락 때문에
팔꿈치/손목 이력을 초기화하지 않는다. 기존 UART 명령·PG/RQ 필드 형식은 변경하지 않는다.
이 입력 거부는 사용자의 명시적 `X`에 의한 토크 해제·내부 궤적 정지와 다르다.

**A 모드는 노출 동기화가 아니다.** 비동기 LIVE는 최근 RIGHT와 가까운 LEFT 입력을 조합하고,
수신 나이 250 ms·수신 시각 차이 100 ms를 제한한다(`time_gate=RECEIPT_LATEST`).
오래된 입력을 버려 대기열 지연을 줄이지만 서로 다른 노출 순간의 오차는 남는다.
`sync=0`, `control=-2`가 유지돼도 별도의 `async_status`와 `accept`로 시험 입력 승인을 확인한다.
`accept`는 입력 어댑터 승인 수이지 실제 서보 동작 성공 수가 아니다. A2/TK/오류 로그를 함께 본다.

`S`, 모니터 종료, USB 연결 해제는 비상정지가 아니다. `q`로 종료해도 보드의 CNN·PWM·추종은 계속 동작할 수 있다.
`X`도 토크를 해제하므로 팔을 먼저 지지한다.
보호 옵션 없이도 `a`, `m`, `x` 등 보드 상태를 바꾸는 키는 전송할 수 있다. 운동 키 차단은 완전한 안전장치가 아니다.
자세한 제어 조건은 [비동기 양안 시험 안내](stereo_async_trial.md)를 참고한다.

## 6. 로그 해석과 저장 파일

기본 tagged 화면에는 UTC 수신 시각과 `[L]`/`[R]`이 붙고 plain 화면에는 `[L]`/`[R]`만 붙는다.
UTC는 **PC 수신 시각**이며 카메라 노출 시각이 아니다. 저장 파일에는 어느 화면 형식이든 UTC를 유지한다.
좌우 프레임 번호도 독립적이므로 번호가 같다는 이유만으로 동기화됐다고 해석하지 않는다.

| 표시 | 확인할 내용 |
|---|---|
| `CN` / `CS` | CNN 프레임 완료·IRQ·성공/오류/timeout 카운터 진행 |
| `TK` | 약 20 ms 로봇 제어 틱과 출력 명령. 로그 존재만으로 PWM ON은 아님 |
| `A1` / `P3` / `A2` | 사람 목표 각도·3D 점·목표 승인/거부 |
| `RAW` | 좌우 각각 CNN 완료 시점의 필터 전 2D 좌표. 양 어깨·사용 팔꿈치/손목·빨강/초록 손가락 마커만 기록 |
| `PAIR` | 오른쪽이 실제 처리한 좌우 프레임쌍. 오른쪽 세션+쌍 순번과 양쪽 세션/sequence/frame ID를 연결 |
| `PIX` | 해당 프레임쌍의 좌우 2D 필터 후 좌표(운영 A는 시간 EMA). RAW와 비교해 필터 전후 튐 확인 |
| `PG` | 해당 프레임쌍의 입력 승인/거부 결과·이유. 계산된 쌍과 로봇 목표 승인을 구분 |
| `[ST] tx`, `drop` | 좌표 송신 프레임 수·송신 대기 프레임 누락. 상대 보드 수신 성공을 보장하지 않음 |
| `[ST] rx`, `crc`, `overflow`, `hw` | 수신 프레임·CRC 오류·RX 링 overflow·UART 하드웨어 오류 |
| `[ST] pairs`, `L`, `R` | 조합된 쌍 수와 사용된 좌우 프레임 번호 |
| `[ST] fresh` | 최근 쌍 생성 여부의 진단. 실제 좌우 입력 나이는 RQ에서 확인하며 노출 동기화 표시는 아님 |
| `[ST] qL`, `qR`, `qdrop` | 좌우 좌표 프레임 대기 큐 길이와 큐 용량 초과 누락 누적 수. USB 화면 큐 누락과 별개 |
| `[ST] time_gate` | `STRICT`는 기본 엄격 시간 검사, `RECEIPT_LATEST`는 수신 나이·간격을 제한하는 async LIVE. 노출 동기화 성공 표시는 아님 |
| `[ST] sync`, `control` | 노출 시간 검증·기본 엄격 제어 경로 상태. 현재 미동기 구성은 0 / -2 |
| `Zmm(wrist,red,green)` | 사용 가능한 유효 점의 depth(mm). async 시험에서는 fresh=0인 마지막 쌍도 표시될 수 있음. 0은 유효 실측 0 mm라는 의미가 아님 |
| `async_test`, `async_status`, `accept`, `reject` | 비동기 시험 ON/OFF·재구성 상태·입력 승인/거부 누적 수 |
| `PG reason` | `STALE/MATCH_GAP`는 오래된 입력/큰 수신 시각 차이. `JUMP_HOLD/REACQ_WAIT/REACQ_ACCEPT`는 150 mm 도약·500 ms 초과 승인 공백·세션 변경 후 후보 보류·확인·재획득 입력 승인 |
| `RQ` | 입력 추적 상태·후보 수·필터 세대·좌우 입력 나이와 수신 시각 차이. A2/PWM 승인과 별개이며 commands 화면에서는 숨기고 파일에 저장 |

LEFT의 좌표 `tx` 증가와 RIGHT의 좌표 `rx`/`pairs` 증가를 함께 확인한다. LEFT는 stereo pair를
직접 만들지 않지만 새 split-board에서는 main A1 각도도 수신하므로 해당 수신 상태를 `l T`로 확인한다.
기존 좌표 송신 전용 BOOT의 LEFT `rx=0`, `pairs=0`은 그 자체로 이상 증거가 아니다.
오류 카운터는 누적값이므로 **계속 증가하는지**를 본다.
오류가 늘면 배선·공통 GND·속도 등을 점검하되 카운터 하나만으로 원인을 단정하지 않는다.
현재 재투영 품질 거부 기준은 좌우 각각 **15px 초과**다. 이는 시험 설정이며 실제 깊이 정확도 보증이 아니다.
운영 A는 삼각측량 전에 좌우 2D 점에 시간 EMA(기본 τ=0.10 s)를 적용하며 30px 초과 변화에는 평활 이력을 이어 쓰지 않고
새 점으로 재시작한다. 별도로 비동기 입력의 팔꿈치·손목 3D 좌표가 최근 승인 좌표에서
**150mm 초과 이동하면 단일 입력을 보류**하고 3개 후보로 재획득한다. 승인 공백이 500 ms를
넘으면 옛 위치 대신 최근 후보의 군집/이동 일관성을 확인한다. 두 조건은 단위와 역할이 다르며
동기화 기능이 아니다. 상세 수치는 [UART 참고 문서](uart_reference.md)를 따른다.
상세 TRACE 필드는 [UART 참고 문서](uart_reference.md)를 따른다.

### 가만히 있을 때 픽셀 튐 측정

최신 LEFT/RIGHT BOOT으로 교체한 뒤 새 모니터 세션을 기록한다. 모니터를 종료하고
`robot_arm` 폴더에서 실제 세션 경로를 지정해 분석한다.

```powershell
python -B tools/stereo_vision/analyze_stereo_pixel_jitter.py --session captures/monitor_YYYYMMDD_HHMMSS_xxxxxx --json jitter.json
```

정지 구간만 고르려면 `--right-session 123 --start-pair 20 --end-pair 200`을 추가한다.
오른쪽 세션 ID와 쌍 번호는 PAIR 로그에서 확인한다. RAW/PIX 표준편차·범위·점프 P95/최댓값,
누락/invalid/PG 거절 개수를 출력한다. 기존 BOOT 로그에는 PAIR가 없어 분석이 실패한다.
이 통계는 2D 필터 전후 비교이며 추가 3D 필터의 효과나 실제 노출 동기화를 보증하지 않는다.

PWM OFF 상태에서도 CNN 추론과 RAW 기록은 계속할 수 있다. 10~30초간 몸·손·카메라를 고정하고
`left_uart.log`/`right_uart.log`의 RAW에서 점별 x/y 표준편차·최대 변화량과 유효 검출 비율을 계산한다.
어깨는 좌우 어깨 관절, 손가락은 빨강/초록 컬러 마커를 뜻하며 17개 전체 관절 로그가 아니다.
좌우 RAW는 각자의 원시 검출 흔들림을 측정하고, 실제 계산에 쓰인 점만 분석하려면 PAIR에 기록된
양쪽 신원과 RAW를 연결한 뒤 PIX와 비교한다. 거부된 쌍도 PG로 분리해 검사 탈락에 따른 선택 편향을 확인한다.
필터 전 RAW에 2D EMA를 적용한 IN/PIX나 3D P3를 섞어 원시 픽셀 정확도로 보고하지 않는다.

좌우 부팅 시각이 달라도 **왼쪽 fid = 오른쪽 fid**로 짝을 찾지 않는다. PAIR의 실제 선택 기록을 사용한다.
세션은 보드별이고 쌍 순번은 오른쪽 세션 안에서 해석한다. 모니터 로그 폴더도 함께 보관한다.
이 정보는 처리 쌍의 출처를 추적하는 수단일 뿐 노출 시각이 일치했다는 증거는 아니다.
정확한 컬럼·valid/score 의미는 수신한 `#RAW`/`#PAIR`/`#PIX`/`#PG` 스키마와
[보드 간 UART 문서](stereo_board_uart.md)를 따른다. 이 로그는 새 펌웨어가 필요하다.
`commands`/`console` 모드는 새 주기적 TRACE도 화면에서 숨기지만 파일에는 수신한 전부를 저장한다.
TRACE_DROP/SM drop 및 ST qdrop이 증가하면 누락·선택 편향을 별도로 기록한다.

기본 로그 폴더는 `captures/monitor_날짜_시간/`이다.

| 파일 | 내용 |
|---|---|
| `combined_uart.log` | 전체 좌우 텍스트, UTC와 L/R 태그 포함 |
| `left_uart.log`, `right_uart.log` | 보드별 전체 텍스트. UTF-8 디코딩·줄바꿈 정규화 |
| `left_uart.raw`, `right_uart.raw` | PC가 읽은 바이트 원본 |
| `host_commands.jsonl` | PC 입력, 전송 대상, 요청/전송 바이트 수, 결과·오류 |
| `session.json` | 포트·속도·모드·종료 상태·수신량·명령 이력 |

모든 필터·화면 형식에서 디스크에는 전체 로그를 남긴다. `[HOST]` 전송 결과는 필터와 무관하게 화면에 표시한다.
화면 큐가 가득 차면 표시만 생략할 수 있으며 `display_dropped`에 누적된다.
USB/OS/UART/디스크 지연까지 무손실을 보장하지는 않는다. 시작 전에 출력된 로그는 복구하지 못한다.

## 7. 자주 생기는 문제

| 증상 | 확인/조치 |
|---|---|
| 터미널에 입력해도 명령이 안 됨 | `--interactive` 여부, 입력 가능한 터미널인지, `r t`처럼 대상이 있는지 확인 |
| E/A/X 등이 차단됨 | 안전 조건을 확인하고 `--interactive --allow-motion-commands`로 재실행 |
| `r m` 이후 값이 적용되지 않음 | `r value 숫자` / `r enter`로 13개 항목을 완료하고 applied 응답 확인 |
| `both` 숫자 메뉴가 엇갈림 | 양쪽 현재 프롬프트 확인 후 `l`/`r`로 별도 진행. both 전송은 원자적이지 않고 자동 복구 없음 |
| 값 유지하려고 빈 Enter를 눌렀는데 진행 안 됨 | 빈 입력은 PC에서 무시됨. `r enter`, `l enter`, 같은 항목일 때 `both enter` 사용 |
| `X` 후 `E`가 계속 거부됨 | 새 상태 정합 소스의 BOOT인지 확인. V 응답·모드·안전검사·HAL 오류 확인; 반복 E나 강제 우회는 해결책 아님 |
| 새 CNN 입력이 거부되고 팔이 유지됨 | PG/A2 거부 이유 확인. 마지막 승인 목표 유지이며 150mm 이력 거부는 오래 지속될 수 있음 |
| 설정 완료 후 CNN이 멈춰 있음 | m 진입 시 자동 추론 중단. OFF 확인 후 해당 보드에 소문자 `a` 전송 |
| 도움말·설정 적용 응답이 안 보임 | `--filter stereo`가 숨길 수 있음. `--filter all`로 재실행하거나 저장 로그 확인 |
| commands 필터에서 응답이 누락됨 | 늦은 응답이면 response-window를 늘리거나 all/전체 저장 로그 확인. 보드 mute·오류 여부 확인 |
| 포트 열기 실패/Access denied | ComPortMaster·기존 모니터 등 해당 포트를 점유한 프로그램 종료 |
| 포트 없음/한쪽 USB 해제 | `--list-ports`로 재확인. 양쪽 연결 후 수동 재실행. 자동 재연결 없음 |
| 양쪽 또는 한쪽 로그 없음 | 속도·좌우 번호·전원·부팅·mute 여부 확인. 기본 화면에서 의도적으로 `l q`/`r q`를 보내면 출력 상태가 토글됨 |
| 글자가 깨짐 | USB 콘솔 baud가 펌웨어와 맞는지 확인. UART0의 115200과 혼동하지 않기 |
| 로그가 너무 많아 입력이 눈에 안 보임 | 명령 작업은 `--interactive --filter commands --format plain`, 장애 진단은 all 사용 |
| HDMI 검은 화면인데 DONE LED는 켜짐 | DONE은 FPGA 설정 완료 표시일 뿐 앱·카메라 성공 보장은 아님. 카메라 초기화 오류 확인 |
| `OV5640 detection failed` | 카메라 ID 검출 실패. 전원을 끄고 카메라 케이블·전원 확인. 이것만으로 케이블 불량을 확정하지 않기 |

현재 BOOT은 초기화 실패 뒤 앱이 종료될 때 UART 송신 버퍼에 오류 메시지가 남아 보이지 않을 수 있다.
실제로 2026-10-02 왼쪽은 JTAG로 보류 로그를 읽어 `OV5640 detection failed`와 SCCB NACK 2회를 확인했다.
**이 모니터 자체는 JTAG나 보드 메모리를 읽지 않으며, 송신되지 않은 오류를 복구하거나 카메라를 재초기화하지 않는다.**
그 상태에서는 콘솔 명령이 처리되지 않을 수도 있으므로 로그가 없다고 정상으로 판단하지 않는다.
전원을 켠 채 카메라 케이블을 재장착하지 않는다.

## 8. 종료와 검증

수신 전용은 `Ctrl+C`, 대화형은 단독 `q` + Enter 또는 `Ctrl+C`로 종료한다.
`l q`, `r q`, `both q`는 보드 출력 토글이므로 PC 종료 명령과 다르다.
한쪽 읽기/전송 오류가 발생하면 양쪽 수신을 종료한다. 부분 전송 후 나머지 바이트를 자동 재전송하지 않는다.
종료 코드: 정상 0, Ctrl+C 130, 오류 1.

보드 없이 스크립트 테스트를 실행하려면:

```powershell
python -B -m unittest discover -s tools/stereo_vision -p 'test_*monitor*.py'
```

스크립트 실행은 BOOT.BIN을 수정하지 않는다. PC 스크립트만 업데이트했다면 기존 실행 프로세스를 종료한 뒤 재실행해야 반영된다.

## 9. RIGHT 손목 선택적 복귀 연결 (2026-10-06)

`stereo_G_wrist_selective_return45_20261006/right/BOOT.BIN`은 승열0 기반 RIGHT 시험 배포본이다.
실제 배포용 소스는 `captures/g_uart_tuning_20261004/G/snapshot`이며 기존 `src` 경로를 이 버전으로 일괄 교체하지 않았다.
승열0의 LEFT/RIGHT BOOT·가중치·소스 백업은 `D:\Working\robot-motion-harness\baselines\승열0`에 보존한다.

- 정상 손목 추종은 유지하고, 범위 재진입 또는 실제 정지 해제에서 목표 차이가 8°를 넘을 때만 복귀 연결한다.
- 새 유효 손목·빨강·초록 3D 관측 1회로 연결한다. 관측 공백이 250ms 초과이고 목표 차이가 60° 초과일 때만 새 관측 2회를 확인한다.
- 2회 확인은 서로 다른 프레임, 80~250ms 간격, 목표 각도 차이 15° 이내가 필요하다. 무효·중복 관측은 확인으로 세지 않는다.
- 연결 목표는 45°/초로 진행하고, 기존 출력 속도·가속도 제한 및 A2/FK 안전검사를 유지한다. 입력이 끊겨도 승인한 목적지까지는 계속 진행한다.
- 필터 epoch 변경만으로 정지 해제를 판정하지 않는다. PWM/세션 제어 초기화에서는 복귀 상태도 초기화한다.
- 속도100%, 팔꿈치 복귀, 독립 그리퍼, 초록 기본값 LEFT25/RIGHT20, 기하 및 JUMP150 검사는 유지한다.

기존 모니터 실행 명령과 `r A`/`r S` 사용법은 동일하다. 이 복귀 계수용 새 UART 명령은 추가하지 않았다.
명령 출력의 안정화 시험이며 실제 서보 위치 피드백이나 CNN 좌표 복원 개선을 의미하지 않는다.

### 정지 중 재진입 예외 보완

후속 RIGHT 배포본은 `stereo_G_wrist_return_hold_fix_20261006/right/BOOT.BIN`이다.
이미 팔 목표를 유지하는 정지 상태에서는 손목 범위 재진입을 새 복귀 확인의 시작으로 처리하지 않는다.
따라서 기존에 승인한 목적지로 연결 중이었다면 연결 상태를 보존하고 45°/초로 계속 진행한다.
미승인 후보를 정지 판정만으로 승인하지 않으며, 실제 정지 해제에서는 기존 신선 관측 확인을 그대로 적용한다.
속도100%·팔꿈치·그리퍼·필터·기하/JUMP·A2/FK 안전검사와 UART 사용법은 변경하지 않았다.
이 수정은 연결을 건너뛰는 예외를 막는 것이며, 정상 추종 속도를 더 낮추거나 모든 손목 떨림을 해결하는 변경은 아니다.

## 10. RIGHT 손목 롤 방향 보정 (2026-10-06)

`stereo_G_wrist_roll_direction_fix_20261006/right/BOOT.BIN`은 위 정지 중 재진입 보완을 유지하면서 A2의 `wrist_roll.direction`만 `+1`에서 `-1`로 바꾼 RIGHT 배포본이다. 사람과 로봇을 같은 방향에서 보았을 때 실제 비틀림이 반대라는 사용자 관찰에 따른 보정이다.

- 기존 목표 `87 + 사람 roll`을 `87 - 사람 roll`로 바꾸고 중립 87°, scale=1, 범위 10~170°는 유지한다.
- 사람 각도 계산식, FK 물리 축 부호, PWM 변환 및 속도100%는 바꾸지 않는다.
- 기존 `src/robot_calibration/forearm_calibration_config.c`와 실제 G 배포 snapshot의 동일 설정을 함께 반영했다. G의 나머지 설정을 기존 `src`에 일괄 복사하지 않았다.
- 팔꿈치·손목 분리 정지 또는 2D 방향/상대 깊이 승인 후보는 외부 시험만 했으며 이 BOOT에는 넣지 않았다.
- LEFT는 변경하지 않는다. 가중치 BIN/SHA, PACK_ID `0x77D4E3BB`, XSA/비트스트림도 유지한다.
- 기존 UART 명령은 동일하다. 파일 설치와 실제 보드 부팅은 별개이며 설치 후 전원을 껐다 켜야 새 이미지가 실행된다.

실물 확인은 초기 자세로 이동할 시간을 준 뒤 손목을 천천히 양쪽으로 비틀어 사람과 로봇 방향이 일치하는지 보는 것이다. 모니터 좌우 반전과 실제 물리 회전을 구분한다. 외부 회귀/파일 검증이 물리 방향과 모든 자세의 안전성을 대신하지 않는다.
