CNN_3D Hand Interaction Platform의 color_marker_detect 모듈을 CNN-v4.0 계약에 맞게 구현하라.
담당: 한승훈. 대상 Zybo Z7-20 / XC7Z020. 언어는 Verilog-2001 .v만 허용한다.
SystemVerilog의 logic, always_ff, always_comb, typedef, enum, interface, package 등 문법은 금지한다.
아래 내용으로 RTL과 self-checking Verilog-2001 테스트벤치를 작성하라. 다른 Notion 페이지를 읽어야만 알 수 있는 계약을 가정하지 마라.
신호명·방향·폭·필드 위치·산술·DSP/BRAM 숫자를 바꾸거나 포트를 추가하지 마라.
데이터/가중치 및 실제 checkpoint 검증에는 원본 파일이 필요하다. 제공되지 않은 자료나 검증 결과를 만들어내지 마라.

[역할과 설계 배경]
`downsample_module`이 실제로 소비한 원본 RGB를 관찰하여 빨강·파랑 두 색상 마커의 중심을 계산한다. 별도 ready 없이 tap_accept=1인 cycle만 처리한다. 좌표는 원본 720p 기준이고 row는 0,5,...715이며 letterbox padding은 입력되지 않는다.

빨강 설정은 {B_max[23:16],G_max[15:8],R_min[7:0]}, 기본값 0x6464A0이다. 파랑 설정은 {B_min[23:16],G_max[15:8],R_max[7:0]}, 기본값 0xA06464다. 빨강은 R>=R_min && G<=Gmax && B<=Bmax, 파랑은 R<=Rmax && G<=Gmax && B>=Bmin으로 판정한다. 두 조건을 모두 만족하면 두 count에 모두 포함한다.

색상별 count18bit와 sumx/sumy 각 28bit를 둔다. 최대 count는 184320, sumx는 235745280, sumy는 131788800이다. count>=MIN_COUNT(기본 8)일 때 found=1이고 그 외에는 x=y=0이다. count0에는 divider를 실행하지 않는다.

28bit numerator/18bit denominator unsigned restoring divider 하나를 공유하고 몫은 floor다. DSP는 0개로 유지한다. 결과 word는 {found bit31,reserved30:21=0,y20:11,x10:0}다. top이 동일 frame_id의 CNN 결과와 함께 commit한다. 이 모듈의 대상은 두 색상 마커다.

## 적용 기준 CNN-v4.0
이 페이지와 generated/interface.json, manifest.json 은 같은 버전이다. RTL 은 Verilog-2001(.v), 검증은 Python 정수 reference 를 사용한다. 클럭은 100MHz, reset 은 동기 active-low rst_n 이다. 자원 배정은 합성 전 예산이며 전체 SoC 합성과 timing 결과로 승인한다.
입력은 1280×720 RGB888 을 256×256 으로 전처리한다. body 는 0..127 을 INT8 로 저장하고 weight 는 signed INT8, heatmap 은 signed INT8, offset 은 signed INT16 이다. 출력채널별 M 은 0..131071 이다. bias_accum=RNE(bias_int8*bias_M/65536)을 PC pack 단계에서 계산하며 signed24 범위를 검사한다. body 누산기는 signed24, conv0 의 doubled 누산기는 signed25 다. 재양자화는 signed25 × signed18 → signed43 전체 곱을 보존한 뒤 RNE ties-to-even 을 적용한다. body/heat/offset 의 saturation 범위는 각각 [0,127], [-128,127], [-32768,32767]이다. Verilog part-select 와 concat 의 signedness 는 명시적으로 변환한다.
RNE 구현식은 q=p>>>N, r=p-(q<<N), h=1<<(N-1), result=q+((r>h)||((r==h)&&(q&1)))이다. N=0 이면 p 를 그대로 사용한다. 음수에서도 q 는 floor 방향이고 r 은 0..2^N-1 이다. 곱의 하위 비트를 먼저 버리거나 양수용 반올림 상수를 더하지 않는다.
valid 는 ready 와 무관하게 assert 할 수 있어야 한다. valid && !ready 동안 data/mask/tag/last 를 유지한다. counter 는 accept 또는 MAC issue 에서만 증가한다. cfg 는 idle 에서 수락하고 완료까지 래치한다. done 은 모듈별 최종 transfer 수락 후 1cycle pulse 이며 top 이 기억한다. 오류는 sticky fault 로 남기고 새 작업을 차단한다. PS 가 DMA 를 reset 한 뒤 core SOFT_RESET 한다. 데이터 RAM 전체를 reset 하지 않는다.
TAG64: col[7:0], row[15:8], batch[19:16], group[26:20], tap[30:27], batch_last[31], pixel_last[32], op_id[37:33], frame_end[38], group_last[39], reserved[63:40]=0. row/col 은 생산자가 내보내는 tensor 의 좌표다. line 입력은 입력 좌표, line 출력은 convolution 출력 좌표다. pixel_last 는 현재 pixel 의 마지막 beat, frame_end 는 현재 operation 의 최종 pixel 최종 beat 에만 1 이다. group_last 는 마지막 출력 group 이다. 미사용 tag 필드는 0 이며 lane0 은 최하위 byte/bit 다.
입출력 tensor 는 HWC, row→col→channel 순서다. cfg_desc256 의 [255:149]는 0 이다. mux 선택은 top 이 cfg 전에 고정하고 선택되지 않은 입력의 ready 는 0 이다. conv0 는 dilation=1, pad=1, stride=2 로 고정한다. DW 는 dilation 1/2 와 stride 1/2 를 지원한다. 제공 manifest 의 d1 은 구현 baseline 이며 원본 체크포인트 확인값이 아니다. export_geometry.py 로 실제 모델의 geometry 를 확인해야 한다.

reset rst_n은 4cycle 이상 assert한다. 위 고정 폭의 raw port에서 signed 연산은 내부에서 명시적으로 변환한다.
모듈에 없는 공용 신호를 추가하지 않는다. color 관찰 tap_accept 및 results_valid처럼 ready가 없는 포트에는 임의로 ready를 만들지 않는다.

[모듈 세부 계약 전문: 기존 CNN-v4.0 기술 조건 보존]
## 역할
downsample 내부의원본 RGB accept tap 을관찰한다. ready 를출력하지않지만 tap_accept=1 일때만처리한다. 입력 row/col 은이미원본 720p 좌표이며 row 는 0,5,...715 다. letterbox 패딩은입력되지 않는다.
## 판정
red24={B_max[23:16],G_max[15:8],R_min[7:0]},default0x6464A0. blue24={B_min[23:16],G_max[15:8],R_max[7:0]},default0xA06464. 빨강 R>=R_min&&G<=Gmax&&B<=Bmax,파랑 R<=Rmax&&G<=Gmax&&B>=Bmin. 두조건동시충족시두 count 에모두포함. threshold 는 frame start 에서 snapshot 한다.
색상별 count18bit(최대 184320),sumx28bit,sumy28bit 를사용한다. 최대 sumx235,745,280,sumy131,788,800 으로 28bit 안에들어간다. 마지막 pixel 도합산한후 divider 를시작한다. count>=MIN_COUNT(default8)일때 found1,아니면 x=y=0.
## 나눗셈
unsigned restoring divider1 개를공유,28bit numerator/18bit denominator,28iteration+load/output2=30cycle/division. redx/redy/bluex/bluey 순서최대 120cycle. quotient 는 floor,동작 중새 frame 거부. count0 은 divider 실행안함. DSP0,use_dsp=no. results_valid 는마지막 division 결과를 register 한후 1cyclepulse,결과는다음 frame 완료까지 hold. top 은동일 frame_id 의 CNN 결과와함께 commit 한다.
## 결과
word={found bit31,reserved30:21=0,y20:11,x10:0}. grayscale/임계경계/최소 count/0count/마지막 pixel 색상/긴 CNN stall 을시험한다. 이검출은 2 개색상마커이며손가락개수 5 개인식모델이아니다.

[레이턴시·reset·stall·종료 요구사항]
frame_start에서 임계 설정을 snapshot하고 누산 상태를 초기화한다. 마지막 pixel을 누산한 다음 divider를 시작한다. 28iteration+load/output2로 division당 30cycle이며 redx→redy→bluex→bluey 최대 120cycle이다. 계산 중 새 frame을 거부한다. 마지막 division 결과를 register한 뒤 results_valid를 1cycle 내고, 결과 word는 다음 frame 완료까지 유지한다.

[반드시 그려 검증할 파형 시나리오]
1. frame_start 전후 설정을 바꾸어 snapshot한 값으로만 현재 frame을 판정하고 누산 상태가 초기화되는지 본다.
2. tap_accept 간격을 길게 벌리고 마지막 pixel만 색상 조건에 맞춰 중복 계수 없이 마지막 값이 divider에 포함되는지 본다.
3. count0, MIN_COUNT-1, MIN_COUNT와 양쪽 색상 동시 일치에서 found·division 생략·분모를 확인한다.
4. 4개 division의 30cycle 구간, 최대120cycle, results_valid pulse 및 다음 frame 완료 전 결과 유지를 본다.

[수락 체크리스트]
- tap_accept에서만 계수하고 임계값 비교에 등호를 포함한다.
- 동시 색상 일치는 양쪽에 포함하고 마지막 pixel도 누산한다.
- ready가 없는 관찰 포트에 backpressure를 임의로 추가하지 않는다.
- results_valid pulse와 결과 유지, frame_start snapshot을 구분한다.
- count0의 division을 건너뛰고 최소 count 경계를 시험한다.
- count18·sum28 최대값과 원본 좌표를 검사한다.
- downsample stall 중 tap 중복이 없는지 통합 검증한다.
- 동일 frame CNN 결과와 publish하고 divider 1개/DSP0을 확인한다.
