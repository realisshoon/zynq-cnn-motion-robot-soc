CNN_3D Hand Interaction Platform의 line_buffer 모듈을 CNN-v4.0 계약에 맞게 구현하라.
담당: 유지민. 대상 Zybo Z7-20 / XC7Z020. 언어는 Verilog-2001 .v만 허용한다.
SystemVerilog의 logic, always_ff, always_comb, typedef, enum, interface, package 등 문법은 금지한다.
아래 내용으로 RTL과 self-checking Verilog-2001 테스트벤치를 작성하라. 다른 Notion 페이지를 읽어야만 알 수 있는 계약을 가정하지 마라.
신호명·방향·폭·필드 위치·산술·DSP/BRAM 숫자를 바꾸거나 포트를 추가하지 마라.
데이터/가중치 및 실제 checkpoint 검증에는 원본 파일이 필요하다. 제공되지 않은 자료나 검증 결과를 만들어내지 마라.

[역할과 설계 배경]
DDR에서 복원된 `feature_map_io`의 32채널 beat를 저장하고, depthwise convolution에 필요한 32채널 탭을 시간 순서로 공급한다. 출력 폭은 256bit다. 3×3 윈도우 전체를 한 번에 배선하는 대신 탭 스트림을 사용하여 BRAM 포트 요구량과 배선을 줄인다.

저장소는 5개 행의 ring이다. 행당 최대 256word, word당 256bit이며 `row_words=win*ceil(Cin/32)`를 cfg에서 래치한다. 64bit bank 4개를 각각 깊이 1280으로 구성하므로 RAMB36은 총 12개다. 주소는 `(input_row%5)*row_words + col*ceil(Cin/32)+batch`다. 필요한 최소 행을 덮어쓰지 않고 row generation tag로 이전 레이어 내용을 무효화한다.

출력 순서는 oy→ox→batch→tap이다. tap t의 ky=t//3, kx=t%3에 대해 `iy=oy*stride-pad+ky*dilation`, `ix=ox*stride-pad+kx*dilation`을 사용한다. 바깥 좌표는 메모리를 읽지 않고 0을 만든다. 따라서 stride에 따른 출력 위치 선택은 이 모듈의 윈도우 주소 생성에 반영된다. 입력을 저장하는 단계에서 홀수 행·열을 버리면 안 된다.

허용 범위는 dilation 1/2, pad=dilation, stride 1/2와 `win*ceil(Cin/32)<=256`이다. 각 탭의 mask는 `(1<<min(32,Cin-32*batch))-1`이다. tap8이면서 마지막 batch일 때 batch_last를 표시한다. 마지막 출력 위치의 tap8·마지막 batch에서 frame_end를 표시한다.

## 적용 기준 CNN-v4.0
이 페이지와 generated/interface.json, manifest.json 은 같은 버전이다. RTL 은 Verilog-2001(.v), 검증은 Python 정수 reference 를 사용한다. 클럭은 100MHz, reset 은 동기 active-low rst_n 이다. 자원 배정은 합성 전 예산이며 전체 SoC 합성과 timing 결과로 승인한다.
입력은 1280×720 RGB888 을 256×256 으로 전처리한다. body 는 0..127 을 INT8 로 저장하고 weight 는 signed INT8, heatmap 은 signed INT8, offset 은 signed INT16 이다. 출력채널별 M 은 0..131071 이다. bias_accum=RNE(bias_int8*bias_M/65536)을 PC pack 단계에서 계산하며 signed24 범위를 검사한다. body 누산기는 signed24, conv0 의 doubled 누산기는 signed25 다. 재양자화는 signed25 × signed18 → signed43 전체 곱을 보존한 뒤 RNE ties-to-even 을 적용한다. body/heat/offset 의 saturation 범위는 각각 [0,127], [-128,127], [-32768,32767]이다. Verilog part-select 와 concat 의 signedness 는 명시적으로 변환한다.
RNE 구현식은 q=p>>>N, r=p-(q<<N), h=1<<(N-1), result=q+((r>h)||((r==h)&&(q&1)))이다. N=0 이면 p 를 그대로 사용한다. 음수에서도 q 는 floor 방향이고 r 은 0..2^N-1 이다. 곱의 하위 비트를 먼저 버리거나 양수용 반올림 상수를 더하지 않는다.
valid 는 ready 와 무관하게 assert 할 수 있어야 한다. valid && !ready 동안 data/mask/tag/last 를 유지한다. counter 는 accept 또는 MAC issue 에서만 증가한다. cfg 는 idle 에서 수락하고 완료까지 래치한다. done 은 모듈별 최종 transfer 수락 후 1cycle pulse 이며 top 이 기억한다. 오류는 sticky fault 로 남기고 새 작업을 차단한다. PS 가 DMA 를 reset 한 뒤 core SOFT_RESET 한다. 데이터 RAM 전체를 reset 하지 않는다.
TAG64: col[7:0], row[15:8], batch[19:16], group[26:20], tap[30:27], batch_last[31], pixel_last[32], op_id[37:33], frame_end[38], group_last[39], reserved[63:40]=0. row/col 은 생산자가 내보내는 tensor 의 좌표다. line 입력은 입력 좌표, line 출력은 convolution 출력 좌표다. pixel_last 는 현재 pixel 의 마지막 beat, frame_end 는 현재 operation 의 최종 pixel 최종 beat 에만 1 이다. group_last 는 마지막 출력 group 이다. 미사용 tag 필드는 0 이며 lane0 은 최하위 byte/bit 다.
입출력 tensor 는 HWC, row→col→channel 순서다. cfg_desc256 의 [255:149]는 0 이다. mux 선택은 top 이 cfg 전에 고정하고 선택되지 않은 입력의 ready 는 0 이다. conv0 는 dilation=1, pad=1, stride=2 로 고정한다. DW 는 dilation 1/2 와 stride 1/2 를 지원한다. 제공 manifest 의 d1 은 구현 baseline 이며 원본 체크포인트 확인값이 아니다. export_geometry.py 로 실제 모델의 geometry 를 확인해야 한다.

reset rst_n은 4cycle 이상 assert한다. 위 고정 폭의 raw port에서 signed 연산은 내부에서 명시적으로 변환한다.
모듈에 없는 공용 신호를 추가하지 않는다. color 관찰 tap_accept 및 results_valid처럼 ready가 없는 포트에는 임의로 ready를 만들지 않는다.

[모듈 세부 계약 전문: 기존 CNN-v4.0 기술 조건 보존]
## 역할
feature_map_io 의 32 채널 beat 를 저장하고 DW 에 32 채널 tap 을 시간 순서로 공급한다. 기존 2304bit 전체 윈도우 출력 대신 256bit 탭 스트림을 선택해 BRAM 포트와 배선을 줄인다.
## 주소와 크기
W*ceil(Cin/32)≤256, dilation=1 또는 2, pad=dilation, stride1/2 만 허용. 5 개 행 ring, row 당 최대 256word, word256bit. bank=64bit lane group 0..3, depth 최대 1280; RAMB36 512×72 모드에서 데이터 64 만 사용하므로 bank 당 3 개, 합계 12 개. lane index byte j 가 channel=batch*32+j 다.
주소=(input_row%5)*row_words + col*ceil(Cin/32)+batch. 실제 row_words 는 레이어마다 다르며 cfg 에서 래치한다. 처음 필요한 bottom row 까지 채운 뒤 해당 output row 의 모든 col/batch/tap 을 출력하고 다음 필요한 행을 읽는다. 읽기/쓰기 phase 를 직렬화해 같은 bank port 충돌을 피한다. 출력에 필요한 최소 행을 덮어쓰지 않으며 ring row generation tag 로 이전 레이어 데이터를 무효화한다.
## 윈도우 생성
출력 (oy,ox), tap t=0..8 에서 ky=t//3,kx=t%3, iy=oy*stride-pad+ky*dilation, ix=ox*stride-pad+kx*dilation. 바깥 좌표는 메모리를 읽지 않고 0 을 내보낸다. 순서는 oy→ox→batch→tap. 각 tap 의 mask=(1<<min(32,Cin-32*batch))-1. tap8 이고 마지막 batch 면 tag.batch_last=1. 마지막 출력 위치 tap8 마지막 batch 이면 frame_end=1.
sync BRAM read1+출력 register1=2cycle 최초 지연, no-stall tap II=1. output stall 때 주소/태그/데이터 hold, issue pipeline 동결. 전체 입력 읽기 완료와 모든 출력 tap 전달 완료를 모두 확인 후 done. bottom/right flush 는 virtual zero address 로 처리한다.
## 시험
d1/d2, stride1/2, Cin24/48/384, 너비 16/32/64/128 을 검증한다. 전체 tensor 를 저장하지 않으며 메모리 초기화를 위해 매 원소를 reset 하지 않는다. reference conv_acc 와 tap 주소를 대조한다.

[레이턴시·reset·stall·종료 요구사항]
필요한 bottom row까지 입력을 채운 뒤 해당 output row의 모든 col/batch/tap을 출력하고 다음 필요한 행을 읽는다. sync BRAM read1+출력 register1로 최초 지연은 2cycle이며 no-stall tap II=1이다. output stall에서는 주소·태그·데이터와 issue pipeline을 동결한다. bottom/right flush는 virtual zero address로 수행한다. 전체 입력 읽기와 모든 출력 탭 전달이 모두 끝나야 done이 가능하다. 데이터 RAM 전체를 reset하지 않는다.

[반드시 그려 검증할 파형 시나리오]
1. cfg 수락 후 이전 레이어 row generation tag가 무효화되고 첫 bottom row를 확보한 뒤 2cycle 지연으로 첫 탭이 나오는지 본다.
2. stride1/2 및 dilation1/2 조합에서 iy/ix, 탭 번호, 출력 row/col을 관찰한다. 홀수 입력도 ring에 저장되어야 한다.
3. tap 출력 중 stall을 넣어 BRAM issue와 응답·출력 태그가 함께 정지하는지 본다.
4. Cin24/48 tail과 bottom/right flush를 진행하여 mask, tap8의 batch_last 및 마지막 frame_end/done 순서를 본다.

[수락 체크리스트]
- stride/dilation을 iy/ix 주소식에 적용하고 입력 홀수 행·열을 누락하지 않는다.
- 9tap 순서, 패딩 0, 마지막 tap의 batch_last를 확인한다.
- 256bit data·32bit mask·TAG64를 함께 유지한다.
- read/write phase와 stall enable을 맞춰 bank 충돌과 응답 유실을 막는다.
- Cin24/48/384, 너비16/32/64/128 및 row_words 상한을 검사한다.
- ring 재사용 시 살아 있는 최소 행을 덮어쓰지 않는다.
- reference conv_acc와 모든 탭 주소를 대조한다.
- feature_map_io→line_buffer→DW 연결과 입력 소진/출력 flush의 이중 완료 조건을 확인한다.

[산출물]
1. line_buffer.v: 위 포트와 고정 파라미터를 사용한 합성 가능한 Verilog-2001 RTL.
2. tb_line_buffer.v: 위 기능·프로토콜·경계조건·통합 연결을 검사하는 self-checking Verilog-2001 테스트벤치.
3. 위 4개 시나리오 각각의 VCD 파형, 사람이 읽을 수 있는 타이밍 그림, 실행 명령과 가공하지 않은 전체 로그.
4. 검사 결과표: 예상값/실제값/판정, no-stall latency와 stall 복구, 포트 일치 여부. 산술 모듈은 정수 reference와 bit 단위 비교. 비산술 모듈은 주소·byte·태그·순서·완료 조건을 비교.
5. 합성 도구를 사용할 수 있으면 DSP/RAMB36/LUT 및 timing 결과. 도구·원본 모델이 없으면 해당 항목을 미검증으로 표시하고 측정값을 추정으로 대신하지 않는다.
완료 기준은 테스트 통과와 명세 일치다. 아래 템플릿의 TODO를 남겨 둔 상태를 구현 완료라고 보고하지 마라.
